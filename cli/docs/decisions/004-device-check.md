# ADR 004：设备检测的呈现与平台边界

状态：Accepted。日期：2026-10-01。

## 决策

`device-check` 默认输出人类可读摘要；Agent 使用 `--json` 或 `--format json`，继续读取既有 `CommandResult` JSON 外层。格式参数仅属于 CLI，不进入应用请求。参数错误、阻断、工具错误和取消也遵循所选格式，不回显原始参数或异常。

本决策仅取代 [003](003-cli-surface.md) 对 `device-check` 的 stdout JSON 要求；其他命令、元数据查询、退出码分类、原件保留、离线核验和兼容入口规则继续有效。[001](001-unified-contract.md) 的活动数据契约不变。

检测覆盖 macOS、Linux、Windows。采集只读，使用系统接口和有超时的查询，不新增依赖。macOS 的可用内存标为估算；Apple GPU 的统一内存不重复记录为独立显存。采集来源与缺测原因逐字段保留。

未指定模型且没有发现模型时，设备检测完成退出 0，结果状态为 `inspected`；推荐仍为阻断，不能被配置生成器当作可运行模型。显式模型要求不满足或资源不足退出 2。磁盘检查绑定输出路径最近已存在的祖先；`--out` 保存既有 JSON 文件，阻断时也保存，不覆盖已有目录。

检测、容量建议和实时测评资格分别表达。CPU/CUDA 建议保持现有预算字段；Metal 仅报告观察到的能力，不增加活动后端枚举。macOS 实时测评与 Windows 批量实时实验的现有限制继续有效。

## 替代方案与风险

全局改为人类输出会破坏其他命令的自动化；按 TTY 自动切换会使管道结果不稳定；把人类摘要写到 stderr 不满足默认人类输出需求。因此只为设备命令提供显式格式。已有 stdout 消费者需要加 `--json`，保存的 JSON 文件仍可由 Windows 配置脚本读取。

系统工具可能缺失、超时或返回不完整字段，降级为 `null` 与稳定原因；内存估算不能替代服务预检。仅白名单保存 profiler 字段，避免写入设备序列号。无模型退出 0 不能扩大为运行资格，因此始终声明 `ready_to_run: false`。

## 验收

覆盖三平台采集模拟、缺测与超时、非法传感器数值、模型与磁盘阻断、输出目录保护、所选格式的错误及取消路径。全库回归与冷启动检查后，在本机执行只读设备检测并核验 JSON 产物；本机结果仅证明 macOS 检测，不构成模型实测或原生 Windows/Linux 验收。接口见 [设备检测](../device-check.md)。
