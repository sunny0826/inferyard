# ADR 054：普通运行采集 CPU 与温度

状态：Accepted。日期：2026-10-20。

## 问题与决定

Studio 通过 `run --config` 执行普通 single。此前该入口使用 `*-memory.v1`，
所以资源图没有 CPU 与温度原件，即使本机采集器已经支持这些指标。

macOS 与 Linux 的普通 single（含 probe、重跑和续测的新运行）改用与 batch 相同的
原生 ResourceSampler。复用现有来源身份、调度、缺测与封存实现，不在 Studio
新增硬件轮询。Windows 的 single 内存路径、batch 资源路径及 KVMem/NInfer 例外保持。

这项决定替代 [ADR 048](048-run-evidence-containers.md) 与容器契约中
single 默认仅采内存的限制。完整 ResourceSampler 也包含换页、外部 CPU 和请求边界
环境观测；新增成本属于本次测量范围，必须计入完整开销，不继承旧采集资格。
不为只取两个指标另造一份较轻的采集器，避免重复维护身份和安全规则。

## 来源与呈现

沿用 schema v3 既有 counter、sensor 和 collector 定义，不增加证据必填字段。
旧内存运行仍按原字节读取，缺失的 CPU 与温度不补采、不补零、不回写。
格式支持与比较结论遵循[血缘规则](../data-contract.md#证据血缘与比较结论)。

Studio 保留逐观测的来源、时钟、单位、序号、读取区间与缺测原因，按来源各保留
最近 600 点。不同温度传感器不合成一个数；使用者选择具体来源查看。
CPU 显示绑定 PID 的单核等效占用率，可超过 100%，不包含子进程。
不再用半秒窗口猜测不同指标属于同一个采样点。

## 验证边界

回归覆盖实际 single 分派、采集、封存及离线读取，并保留旧内存证据支持；
Studio 覆盖同 UTC 多来源、跨 tail、计数器身份/尺度/分量变化、缺测与每来源窗口。
页面与原生模拟分别验证来源选择、曲线与数值。
本机只读原生采集、模拟服务链路与真实模型测评分别记录，不相互替代。
