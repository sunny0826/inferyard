# 资源、稳定性与条件指标

本文件是[指标定义](metrics.md)的一部分，也是 catalogue 的生成源；共同记录与计算规则见该文件第 1 节。

## 4. 资源与环境：8 组

系统/服务/引擎/设备层指标分列，不相加为所谓总内存。指标归属正式 C+F 请求窗口；基线、预热、取消、无效及残留活动另列。采样观测峰值不等于真实瞬时峰值。

| ID  | 指标             | 计算与单位                                            | 适用性与验收重点                                                                                                |
| --- | ---------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| C01 | 最低系统可用内存 | 正式窗口 MemAvailable 最小值，bytes                     | `/proc/meminfo`；缺段给覆盖与限制；不能称模型独占内存                                                           |
| C02 | 服务RSS峰值      | 绑定 PID/starttime 正式窗口 RSS 最大值，bytes             | 不采客户端 RSS；子进程范围显式；PID 变化停止该来源                                                                |
| C03 | 服务RSS增量      | 正式 RSS 峰值−预热后空闲基线中位数，bytes               | 明确基线窗口；可为负不截为 0；不是模型权重大小或泄漏量                                                           |
| C04 | 服务CPU时间      | 同 PID/starttime 两累计样本间用户态＋内核态 CPU 秒差      | 保存实际 sampled_start/end 与覆盖比例；部分窗口只称观测区间 CPU 时间；完整请求值须边界证据齐全；计数回退/重启为缺测 |
| C05 | 服务CPU利用率    | ΔCPU 秒/同一对累计样本的Δ墙钟秒×100%，100%为一个逻辑核 | 不能用部分样本 CPU 差除整个请求 E2E；整机归一化率另名并记录可用 CPU 数/cpuset                                        |
| C06 | 换页活动         | pswpin/pswpout 累计差，pages 与按实测页大小换算 bytes    | 系统层；zram/swap 环境注明；不归因到单模型；计数回退不可算负交换量                                               |
| C07 | 温度             | 对已知 sensor/domain 报告时间线与观测最高°C             | 只读能力探测；权限/来源不明为 null；不能凭升温断言热降频                                                         |
| C08 | 频率             | 按来源报告 per-core/policy 频率时间线，Hz               | 声明 requested/reported/effective；来源语义不同不可混排；不把请求频率当实际执行频率                              |

每个 collector 记录读取起止、配置/实际间隔、丢样、开销与 phase。C04/C05 需在可归属边界采样；窗口内不足两个可核验累计值则 null，不用运行前后无关样本填补短请求。覆盖不足按指标降级，不删除慢请求。

## 5. 长度与重复稳定性：7 组

| ID  | 指标                        | 计算与证据                                                                        | 不能推出的结论                                                                 |
| --- | --------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| X01 | 输入长度—接受/完成/质量曲线 | 每个实际输入档列 P、拒绝数、C/D、Q/D、延迟与资源；固定模板计数与输出预算           | 服务接受长输入不等于理解有效；最末通过档不等于理论极限                         |
| X02 | 材料位置/多证据正确率       | 每个长度×位置×题族的正确数/有效执行数；文本 hash 与真实 token 数                      | 单针命中不代表长文理解；变体不作独立题数量                                     |
| X03 | 输出预算达成与结束分布      | 实际输出量、预定目标、finish reason、预算耗尽；严格定长轨另列达到目标数/D         | 自然回答提前 EOS 不是执行失败；未生成到上限不等于不支持输出长度                  |
| S01 | 分窗延迟漂移                | 冻结早/晚窗口或逐窗口 L03，报告中位差/比值及样本/失败率                            | 样本组成应相同或按 case 配对；漂移不等于热降频                                 |
| S02 | 空闲点RSS漂移               | 相同探针周期结束并确认 idle 后 RSS 差/时间序列；重启对照独立                          | 缓存与保留池未排除时不能宣称泄漏                                               |
| S03 | 重复任务通过一致性          | 每 case 各轮 pass/fail；全 k 轮通过题数/预定做满 k 轮的去重 case 数；未完整 k 轮则整包值 null | 例如 30 题全 3 轮通过为 30/40，不含只跑一轮的新 80 题；不称修复重试成功率或标准 pass@k |
| S04 | 运行间性能波动              | 相同 case/负载各完整 trial 中位数、范围、IQR 与配对差                                 | 三轮只描述已观测变化；不能凭少量相关数据作泛化显著性结论                       |

S03 例子中的“新 80 题”指组合包在基础包 40 题之外扩展的四类 80 题，题包组成见[实验设计](design.md)。

持续负载用固定发送窗口，结束后排空至冻结 deadline；窗口末仍在途的请求保留到最终终态。按发送时点归属请求队列、按完整请求报告延迟，资源时间线另保留排空段，不能截掉窗口末慢请求。比较早晚时固定相同探针组成，并冻结 `min_completed_per_case_per_window`；不足则 S01 差值/比值为 null，不能借用 P95 的 20 样本呈现规则。

本地容量预检未发送与资源安全停止后的未发送项记录 not_executed 及原因。服务拒绝已发出的合法请求（例如 400/413/503 容量或能力错误）、OOM 或超时，均按冻结协议记 F 及具体原因，不能因 HTTP 未接受就删除分母；工具发出违反冻结协议的请求时记 invalid，并保留归因证据。所有未测档可见，不把未测写成“不支持”。

## 6. 有条件扩展：9 组

以下条件指标按[扩展验收要求](design.md#条件扩展的验收)分别验证来源、接口与实际设备；条件不满足时保留原因，不用估算值填充。

| ID  | 指标              | 计算边界与证据                                                                                 |
| --- | ----------------- | ---------------------------------------------------------------------------------------------- |
| E01 | GPU内存观测峰值   | 按设备/进程/引擎层分别采样 bytes；统一内存不能与 RSS 相加；关联具体设备和进程证据                 |
| E02 | GPU利用率         | 按厂商指标定义/刷新周期记录%；不是算力效率或模型 GPU 驻留证明                                    |
| E03 | 功率              | 明确 CPU package、GPU board 或整机插座，W；硬件计数差推导的是窗口平均，不冒充瞬时读数            |
| E04 | 能量              | 同域能量计数差处理回绕，或同范围功率时间积分，J；覆盖缺段不静默插值为完整测量                  |
| E05 | 每成功任务能量    | 冻结批次所有执行尝试能量/质量成功任务数，J/成功任务；零成功为 null；预热/加载是否计入须单独命名 |
| N01 | 请求吞吐          | 固定批次 `C/(最后终态−首次正式发送)` 秒；失败/排空留在分母时间；开放/封闭协议分开                  |
| N02 | 达标吞吐goodput   | 同时满足预注册质量和时延要求的请求数/同一批次秒数；阈值运行前冻结                              |
| N03 | 真实ITL与服务排队 | 两个子项分别存：同 token 序列的逐 token 事件间隔；同服务端时钟执行开始−入队；缺真实事件则各自 null  |
| U01 | 启动到可用时间    | 托管或外部可核验的启动事件→就绪→首个有效答案分别记录；热启动/新进程/OS 缓存状态分开             |

N03 为一组条件观测目录，ITL 和排队不是同一数值、不能合成。U01 在服务生命周期边界扩展前仅允许有完整外部时间证据的导入，不能用服务探测耗时冒充启动时间。

Linux powercap 的 RAPL 暴露能量计数及计数范围；package 和子域可能包含关系，不能相加重复计量，也不能声称为整机插座功耗。[Linux powercap 官方文档](https://docs.kernel.org/power/powercap/powercap.html)
