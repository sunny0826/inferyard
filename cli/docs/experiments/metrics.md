# 指标定义与验收

本文件与[资源、稳定性与条件指标](metrics-resources.md)共同定义 36 组核心与 9 组条件指标，两者都是 catalogue 的生成源；手算用例见[指标验收用例](metrics-acceptance.md)。指标定义版本 `phase2.v1` 与活动数据格式 `schema_version = 3` 分别管理；定义存在不表示每个平台均可采集或已实测。任务规则见[实验设计](design.md)，平台与证据见 [README](../../README.md)。

目标不是凑指标数量，而是每个启用指标都能回答一个问题、给出证据、重算并判断可比性。两份文件的表格共 36 组核心指标、9 组条件指标；同一指标的 P50/P95 或分组曲线不重复计数。

## 1. 共同记录与计算规则

每个指标定义至少包含：`metric_id / definition_version / unit / layer / source / window / applicability / required_capabilities / aggregation / comparison_policy`。观测/汇总附 `value / status / missing_reason / sample_count / numerator / denominator / excluded / evidence_refs`；不适用的字段可省略，禁止使用含义不明的 0 或空字符串。

`evidence_refs` 的外层绑定真实物理文件字节；layout2 的输入、观测和请求另带成员定位及内容摘要，
见[运行原件容器契约](../contracts/run-evidence-layout.md#来源引用与外部绑定)。文件合并不改变
指标 ID、单位、样本范围或比较资格；旧 layout1 引用按保存的原物理含义核验。

层次区分请求、进程、设备、引擎与整机；缺测原因至少覆盖未支持、权限不足、传感器缺失、窗口无样本、边界不可识别、原证据缺失、计数来源改变和样本不足。支持状态、模型能力和本次是否纳入分别记录。

以下基础集合按冻结计划中的一个题型/实验单元计算：

- `P`：计划请求数；`C`：协议完整完成；`F`：有效执行但超时/断流/服务错误；`D=C+F`。
- `P=C+F+cancelled+invalid+not_executed`，五终态互斥。准备/探测/预热不进入正式分母。
- `Q`：完成且通过评分的请求。失败 F 按质量未通过处理，部分正确答案不抵扣失败；评分器错误是 unscorable，不改变执行状态。
- 完整质量轮次要求全部应测项有效执行且可判质量。取消、无效、未执行或无法评分时仅展示子集与计数，正式整包成绩为 null；纯性能包质量为不适用，不因此不完整。
- 零分母为 null。预算耗尽但协议完整属于 C，`budget_exhausted=true`，按实际答案评分；预算耗尽不是自动失败。结束事件缺失/断流属于 F。
- 资源缺测不改变执行与质量；环境变化按指标影响范围降低性能可比性。输出/字段不能为了提高分数被自动修复或补全。

固定时窗持续负载单独定义完整性：事前冻结循环探针、时长、请求安全上限、停止与排空政策，每个请求先持久化身份再发送。P 为本次已登记请求数，仍按五终态守恒；未使用的上限槽位不计 not_executed。到时按协议停止发送并完成排空、所有已登记请求归入 C/F 且必需证据齐全才是完整持续实验；提前安全停止/触发请求上限/工具中断为未达时长。分窗质量只描述已执行探针，不冒充完整 120 题成绩。

百分比同时给分子/分母；差值以百分点或原单位表达。所有正式指标均保留原始值，不只存格式化百分比。

## 2. 执行与质量：12 组

各项按定义、来源和冻结窗口计算；实现状态由安装包 catalogue 记录，真实采集资格绑定本次设备与证据。

| ID  | 指标             | 定义与分母                                         | 必要证据与比较限制                                                                                          |
| --- | ---------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| R01 | 完成率           | C/D；并列五终态、P 和实际执行数                     | 终态事件；不完整仅作已执行部分观察，不算整包差值                                                            |
| R02 | 超时率           | timeout/D                                          | 错误原因与冻结 deadline；用户取消不混入超时；工具自动 deadline 应算超时                                      |
| R03 | 失败类型率       | 每个互斥主错误类型数/D；未知单列                   | 保留原 error；按首个有证据的原因分类，不把连锁取消算多次故障                                                 |
| R04 | 输出预算耗尽率   | D 中 budget_exhausted 为真的请求数/D；另列 C 中的耗尽数 | 原 finish reason、输出预算；cancelled/invalid 中的耗尽另列诊断不入分子；耗尽不决定答案是否正确                |
| Q01 | 分类别整题通过率 | 各类 Q/D；不将六类合成一个总分                      | 评分器、题包、答案处理版本；失败纳入分母；另给每轮值                                                        |
| Q02 | 约束通过率       | 通过的预注册约束数/所有有效尝试应检约束数          | 单独标识计分约束，内部解析/非空检查不重复算内容约束；失败的约束计不通过                                     |
| Q03 | 严格JSON解析率   | 通过严格 JSON 解析的请求数/结构化任务 D               | NaN/Infinity、重复 key、围栏、解释文字按冻结规则；不先修复再解析                                             |
| Q04 | Schema合法率     | 满足指定 Schema 的请求数/结构化任务 D                 | 冻结 Schema 版本及实现；解析失败计不合法；Schema 合法不等于语义正确                                            |
| Q05 | 字段准确率       | 正确字段路径数/所有有效尝试应输出字段路径数        | 固定必需字段和数组匹配策略；解析失败/执行失败全部字段计错；缺字段不删分母，额外字段另影响 Schema/整题        |
| Q06 | 材料问答EM       | 规范化后精确命中允许答案数/问答任务 D               | 固定 Unicode、空白、标点等规范化，不运行后扩充同义答案；开放式语义评分不混入                                 |
| Q07 | 数学逻辑正确率   | 正确答案数/数学逻辑任务 D                           | 明确绝对/相对误差、单位、答案提取规则；NaN 与无穷非法；不执行模型代码                                        |
| Q08 | 分类macro-F1     | 固定 K 类各 F1 平均；F1=2TP/(2TP+FP+FN)                | 非法标签/执行失败进入预定无效预测列，真类计 FN；K 类固定，不删除无人预测类别；零分母类按冻结约定并显示 support |

Q03/Q04/Q05 同时展示：JSON 可解析、Schema 合法、字段正确和整题通过；不能用其中之一代表其他三个。所有 Q 指标的成功贡献须来自 C，F 即使部分输出可解析且内容正确也不计通过，仅保留诊断信息。强制格式与自然输出是不同协议。

## 3. 延迟与速度：9 组

客户端使用同一单调时钟：`t0` 发送，`tc` 首非空生成内容，`ta` 首可识别答案，`tl` 末内容块，`te` 协议完整结束。reasoning 可影响 tc，不一定影响 ta；界面渲染时间不在当前客户端计时边界内。

| ID  | 指标            | 计算与单位                           | 适用性与验收重点                                                                                                 |
| --- | --------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| L01 | 首内容延迟      | (tc−t0)，ms                          | 排除元数据、心跳、空内容；块接口称首内容，不声称逐 token TTFT                                                     |
| L02 | 首答案延迟      | (ta−t0)，ms                          | 能可靠区分答案/reasoning；完整空答案为 null/no_answer_event；同时保留质量失败                                     |
| L03 | E2E分布         | (te−t0)，ms；min/P50/P95/max、样本数 | 仅 C 且计时有效；并列超时率/预算与排除量；超时不得以 deadline 补入完成分布                                           |
| L04 | 端点输出吞吐    | 端点输出 token 数/E2E 秒，token/s       | 使用同次请求 usage，记录范围；非 decode 速度，不做跨 tokenizer 排名；缺计数为 null                                     |
| L05 | 内容块间隔      | 相邻非空生成块到达时间差，ms         | 接收端在脱敏缓冲前记录到达时间/通道/序号等纯元数据，不保存敏感原文；同请求至少 2 块；不是 ITL，分块策略不同不可比较 |
| L06 | 引擎prefill速度 | 实际未缓存处理输入 token 数/prefill 秒  | 需要同请求阶段计时与缓存定义；TTFT 不能代替；完整缓存命中且处理量 0 时不产生速度                                    |
| L07 | 引擎decode速度  | 引擎定义的生成 token 数/decode 秒       | 冻结首 token、思考/特殊 token 范围与计时定义；不能用 E2E 减首内容反推引擎时长                                         |
| L08 | 客户端解码间隔  | (te−tc)/(端点输出 token 数−1)，ms     | 仅 `compare-engines` 计算；输出 token ≤1 或无 tc 为 null；含首内容后的全部输出与测量开销，不是引擎 decode 速度或 ITL |
| L09 | 首正文延迟      | (tb−t0)，ms                          | 仅 `compare-engines` 计算；tb 为 content/reasoning 累积后去掉开头 `<think>` 仍非空白的首个事件；无正文为 null       |

L06/L07 为核心数据契约和适配器扩展点；实际 Prism 构建是否可读须实测确认，无接口则 null。上游 llama-server 文档描述了 `timings` 及缓存/输入/生成计数；这是适配依据，不是 Prism 分支已通过的证据。[llama-server 官方说明](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

统计默认按**题型/负载档/轮次**分组，不把长短任务混成一个性能结论。L01/L02 的主分布也仅取 C；失败中已观测首事件可作为独立诊断分布。L05 先给逐请求统计，禁止把长答案产生的更多块当作更多独立请求。

v1 测评落盘的 content/reasoning 文本可能经脱敏缓冲延后、拆分或合并，不能据此还原接收块间隔；v1 缺少原块元数据时 L05=null/evidence_missing。L01/L02 可使用已有的脱敏前首事件时间戳，不依赖落盘文本块边界。

分位数算法冻结，宜使用 nearest-rank：排序后第 `ceil(p*n)` 个。P50 在偶数样本时与 v1 测评的两中位均值可能不同，应注明定义版本。原 v1 测评 median 继续按原定义显示，不静默改名覆盖。

本项目的呈现规则：n < 20 不显示 P95，返回 insufficient_samples；20 ≤ n < 100 可展示 P95，但标探索性；n ≥ 100 仍应给样本构成/相关性限制，不自动意味着可靠尾延迟。此为呈现规则，不是统计充分性的行业阈值；核心不承诺 P99。每格 5 次扫描只展示全部点、中位数和范围。

## 8. 与方法目录的关系

方法目录的类别号与类内编号形成稳定 ID，保存原名和版本，不因重排重新编号。目录范围大于当前自动化能力；不能用“条目齐全”宣称全部方法已实现。

| 方法目录覆盖方向               | 对应指标                                |
| ------------------------------ | --------------------------------------- |
| 兼容性、基础能力、中文、结构化 | R01–04、Q01–08                        |
| 内存、性能、上下文             | C01–08、L01–09、X01–03               |
| 配置/量化、稳定性              | S01–04 及受控配对                       |
| 设备、身份、统计、证据         | 所有指标的资格、来源和谱系              |
| 能耗、并发、启动维护           | E01–05、N01–03、U01；分别验收的条件项 |

通用计量背景见[方法执行说明 P2–P5/P9](../reference/methods-guide.md)，活动执行与质量语义以[数据契约](../data-contract.md)及本文件为准。模型答错与执行失败分开，不能为得到有利结果改变分母。
