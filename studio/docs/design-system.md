# Studio Design System

本规范面向 Studio 页面设计、开发与验收。适用六个主页面、运行详情和主窗口内报告视图。
以 onevra v0.2026.10 为组件基线，它构建在 MyGo v0.5.4 之上；CLI 生成的报告正文继续遵守
[报告契约](../../cli/docs/contracts/report-contract.md)。

本规范由模型页已有视觉规格扩展为全局规则。本文是目标规范，不代表现有页面已经全部满足；
当前差距见[页面审查](design-system-audit.md)，未完成工作集中在
[backlog](../../cli/docs/backlog.md#inferyard-studio-后续工作)。

## 页面结构

用户进入一页时，先看到当前状态与下一步，再看到可操作内容和解释依据。
每页有一个一级标题，卡片标题为二级标题，卡片内部独立分区为三级标题。
标题除了字号和字重，还须设置 `Role(ui.RoleHeading).Level(...)`。

主窗口使用 onevra `shells/sidebar.Shell`：可折叠、可拖拽调宽的侧栏，配浮动 header 与内容区；
侧栏默认 205 DIP 宽，折叠与宽度选择在会话内保持（跨折叠与页面切换）；窗口几何经 StateKey 跨会话恢复。顶部不提供通用“刷新”按钮；
固定右上角状态行空闲时显示「引擎 已停止 · 队列 空」。有非终态运行或引擎未停止时，后台刷新与操作不替换引擎、队列状态；其余情况下，刷新或执行操作时显示「执行中」。
模型页、有非终态运行或 busy 时隐藏「停止」；其他页面在引擎 starting/running 且无非终态运行、无 busy 时提供停止。
侧栏上方「新任务」打开 Dashboard，此时无导航项选中；默认打开报告。
侧栏保持报告、模型、下载、设备、设置的顺序，用 onevra `components.Sidebar`/
`components.SidebarItem` 配 lucide 图标；
缺 CLI、目录或模型时仍能进入每一页。运行详情属于 Dashboard，提供明确返回入口。
每页和详情分别保存滚动位置，刷新不把用户带回顶部；表单草稿不被后台刷新覆盖。

| 页面 | 首要内容与主操作 |
| --- | --- |
| Dashboard | 当前阶段、阻断原因与下一步；环境准备、启动、取消、续测 |
| 设备 | 硬件快照与采集状态、行内缺测原因；刷新设备或前往设置恢复，不提供工作区设备检查和数据来源明细 |
| 模型 | 先引擎后模型的选择框、组合状态与「用这个组合新开任务」、只读的本机运行服务清单 |
| 下载 | 仅有任务时显示清单（引擎在前，取消/重试/实际目录名）；同一卡先推荐引擎、后模型，URL 预填且可编辑，只接受 HTTPS；凭证环境变量名折叠在「需要凭证时」；目录名取自设置 |
| 运行详情 | 任务身份、状态、冻结分母下的进度、题目与资源；返回和取消 |
| 报告 | 历史任务在前、报告列表在后；打开为主操作，另做报告折叠；仅 next_action=verify 且报告未核验时显示核验 |
| 设置 | 路径编辑与保存；各路径的副作用在 Dashboard 的环境准备区说明 |

Dashboard 有活动任务时按任务内存状态驱动，否则恢复 `progress.v1` 阶段。环境缺项合并为「准备环境」；阶段标签为准备、设备检查、benchmark、启动与绑定、运行、报告。阶段动作区只渲染当前阶段，不显示运行历史、快速运行与任务队列卡。进入运行后，模型服务收起至固定右上角；排队、运行、取消收尾及活动任务的题包切换期间不展开服务卡。运行结束后的恢复操作见[子系统参考](../../docs/subsystems/studio-panel.md#运行路径)。新任务等待绑定与运行取消后回到共用引擎和模型选择；任务报告完成区域只显示「查看报告」按钮，直接打开本次报告；不显示输出路径或生成成功文字。

模型页按选择区（先引擎后模型）、组合状态区、只读服务卡组织；「用这个组合新开任务」复用「新任务」入口并保留所选组合。服务或测评运行期间组合显示为文字；空清单仅显示「到下载页」按钮。遗留引擎仅警告，不提供恢复或组合新任务按钮；恢复操作留在任务页。
下载任务集中在下载页。其他页面可以折叠低频诊断信息，但当前阻断原因、
失败恢复动作、必要输入和关键缺测原因必须直接可见。原始字段树只用于诊断或原始参数。

## 布局与尺寸

MyGo 布局使用 DIP。以下数值来自现有主窗口与模型页，作为默认密度下的基线；
不把 DIP 当成屏幕物理像素，也不要求复刻 HTML 的字体度量或字距。

| 项目 | 基线与用途 |
| --- | --- |
| 初始主窗口 | 1120 × 800；这是初始尺寸，不是已验证的最小窗口 |
| 侧栏 | onevra Shell 侧栏默认 205 宽，可折叠、可拖拽调宽；缩放时保证标签和键盘焦点可见 |
| 内容外边距 | 24，约 `t.Space(6)` |
| 主要区块间距 | 16；模型页列间与卡片间可用 20 |
| 卡片 | 内边距 18，圆角 8（跟随 `theme.Onevra` 的 `Radius`）；普通内容间距 10 |
| 紧密内容 | 4、8；表单或操作组 10、12；不按单个页面随意新增刻度 |
| 边框 | 1，使用 `t.Border` |
| 模型页宽布局 | 左右约 1.2:1，右栏最小宽 310 |

新组件用 `t.Space(...)` 表达间距与尺寸，在共享组件中维护语义名称。
18 可用 `t.Space(4.5)`，12 可用 `t.Space(3)`；现有常量迁移不得改变控件焦点和可点击区域。
保留 MyGo 控件默认内边距、行高、禁用态与焦点环，避免为对齐截图压缩操作目标。

宽布局只有在两栏都能容纳内容时启用。空间不足或文字放大时改为单列，模型页顺序为选择区、
运行区、本机运行的服务；操作组允许换行。不要仅缩小字体或裁掉按钮来适应窗口。
表格允许自己的横向滚动，页面其余内容保持纵向阅读。

路径、URL、哈希和运行 ID 可选择复制；需要截断时提供完整值的可访问展示或复制入口。
阻断原因和恢复动作不截断。图表图例与长按钮行随可用宽度换行。

## 颜色与字体

颜色取自 `theme.Onevra` 调色板（暖中性色配 terracotta 强调色），由 `shells/sidebar` 在
`ShellOptions.Theme` 安装，浅色/深色跟随 `mygo.Theme.SetSource` 并随系统高对比度变化。
背景使用 `Background`，卡片使用 `Surface`，主文字使用 `Text`，次要说明使用 `TextMuted`，
分隔线使用 `Border`。正文和交互区域不硬编码浅色背景或黑色文字。

HTML 原型与样式对照使用调色板实际值（来源：onevra `theme/theme.go` 的
`LightPalette`/`DarkPalette`，升级 onevra 时复核）：

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| `Background` | `#fcfbf9` | `#211f1c` |
| `Surface` | `#fefefd` | `#2b2925` |
| `SurfaceHover` / `SurfacePressed` | `#eceae4` / `#d9d7d2` | `#36332e` / `#403c36` |
| `Border` | `#deded5` | `#504b43` |
| `Text` | `#33332f` | `#eeeae2` |
| `TextMuted` | `#72726a` | `#bdb6aa` |
| `Accent`（terracotta） | `#bd481b` | `#ed986e` |
| `AccentText` | `#ffffff` | `#291b14` |
| `Success` | `#059669` | `#79bea1` |
| `Warning` | `#b45309` | `#e6b567` |
| `Danger` | `#b4444c` | `#e58f95` |
| `Selection` / `Focus` | `rgba(230,101,43,.22)` / `rgba(185,71,22,.55)` | `Accent` 24% / 80% 透明度 |
| 圆角 `Radius` | 8 | 8 |

| 语义 | 主题颜色 | 使用条件 |
| --- | --- | --- |
| 当前操作、活动状态 | `Accent` | 当前阶段、下载中、启动中、取消中 |
| 已确认成功或就绪 | `Success` | 获取完成、健康检查通过；不据此暗示绑定或证据已核验 |
| 需要处理的限制 | `Warning` | 阻断、部分结果、存活提示无法确认 |
| 失败 | `Danger` | 操作失败、工具或证据错误 |
| 中性 | `TextMuted` | 尚未配置、等待、已停止、已取消 |

状态必须有文字，不能只靠颜色。相同业务语义复用同一呈现映射；不同领域分别映射，
例如引擎 `running` 表示服务已就绪，测评 `running` 表示工作尚在进行。

沿用模型页的低饱和背景：状态面板可用 `color.Mix(t.Surface, 0.93)`，
徽章可用 `color.Alpha(0.10)`。这些是起始配方，不是对比度已经合格的证明。
高对比度下必要时增加清晰边界、使用主题默认表面；关键文字不得通过降低透明度弱化。
模型推荐区可以保留现有轻微主题渐变，不把它扩展到每个卡片；普通内容无需阴影或装饰底纹。

正文继承主题字体与 `FontSize`，代码、路径和安全命令按需使用等宽字体。
项目字号层级建议以 `t.Rem(...)` 表达：页标题约 1.7、卡片标题约 1.3、
状态结论约 1.4、指标约 1.35、辅助文字约 0.85。该比例是本次项目约定，
不是 MyGo 官方要求。默认密度下辅助文字目标不小于 12 DIP；错误和操作条件使用正文尺寸。
现有 24/18/20/19 DIP 标题与指标可作为迁移对照，10 DIP 步骤文字须提高可读性。
文字缩放时容器也须扩展或换行，不能只调整字号。

## 组件用法

| 组件 | 约定 |
| --- | --- |
| 页眉 | 一个一级标题，可有短说明；eyebrow 可选，不用它替代标题或导航 |
| 普通卡片 | 二级标题、相关内容与就近操作；避免多层同款卡片嵌套 |
| 状态面板 | 中文状态、结论、原因或下一步；代码放在次要诊断位置 |
| 键值组 | 标签和值有语义关联；值可复制；缺测原因靠近值 |
| 任务卡 | 类型、名称、状态、指标、操作、输出与错误；以任务 ID 保持稳定身份 |
| 步骤条 | 显示阶段名称和当前阶段；单个当前节点；重复名称仍按位置区分 |
| 步骤轨道 | Dashboard 当前阶段的行动区：编号圆点加纵向连接线，内容铺在页面背景上不用卡片；只渲染当前阶段；轨道标题与卡片标题同为二级 |
| 表格和列表 | 容器有 `Label`；稳定行 key；选择后操作可通过键盘到达 |
| 通知 | 成功可用 Toast；错误保留在操作附近或页内，不能只显示瞬时消息 |

优先使用 onevra `components` 包的控件，并保留 MyGo 布局原语与 `ui.Field`。
不以可点击普通文本替代标准按钮。共享组件的现状见
[components.go](../internal/pages/components.go)与[通用辅助函数](../internal/pages/shared.go)；
标题、活动进度、按钮换行与公告集中在
[design_system.go](../internal/pages/design_system.go)，字段校验提示集中在
[form_validation.go](../internal/pages/form_validation.go)。软件回归与原生验收范围分别记录在页面审查中。

下列保留 MyGo 原生实现，理由是 onevra 没有等价能力：

| 保留项 | 原因 |
| --- | --- |
| 标题：`ui.Text` 配 `Role(ui.RoleHeading).Level(...)` | onevra `Text` 不提供标题角色与层级无障碍语义 |
| 表单标签与错误关联：`ui.Field` | onevra 不提供等价的标签/错误关联外壳 |
| 布局原语：`ui.Row`、`ui.Column`、`ui.Scroll`、`ui.Toolbar`、`ui.Grid` 等 | 页面外层布局骨架仍由 MyGo 布局原语承载 |

依赖许可：onevra 为 MIT；其适配自 MyGo 的部分保留上游 MIT 声明，lucide 图标为 ISC/Feather MIT。

## 表单与操作

输入均通过 `ui.Field` 关联标签，标签说明用户需要输入什么。必需项、默认来源、格式和
成对条件用字段说明表达；占位符不能代替标签。错误用字段 `Error` 或控件 `Error`
关联到具体输入，并在页内保留整体失败结果。服务器和 CLI 校验仍然有效。

每个操作组有明确主操作。页面同时存在安装、保存、初始化等独立流程时，每组最多一个
主按钮，并按当前下一步突出其中最相关的一组。设置页仅路径区的“保存”使用主按钮，下载目录名操作使用普通按钮。按钮用动词与对象命名，例如“保存”
“准备环境”“运行 benchmark”“请求取消”；这些操作不可合并为含糊的“确定”。

禁用状态旁说明缺少的条件。提交后保留输入，阻止重复执行并显示正在处理的对象。
取消请求发出后显示“取消中／等待收尾”，直到终态到达；不立即显示“已取消”。
普通可恢复操作不增加确认框；单题包等契约要求的显式选择仍保留。

成功 Toast 使用 MyGo 自带公告能力。异步错误、阻断或页面变化没有 Toast 时，须提供
一次性辅助技术公告或合理的焦点转移；不能在每次渲染或每个采样点重复播报。
刷新不抢焦点；关闭对话框或返回列表后恢复到合理位置。

## 状态、空态与错误

首次读取、后台刷新、无数据和读取失败分别表示。刷新可保留已有内容并标明正在更新；
失败时保留错误和恢复入口，不能同时暗示仍在正常加载。

空态包含对象、原因或准备条件、下一步入口。尚无报告时指向新任务或「从历史运行另做报告」；
没有来源 run 时指向启动测评；设备快照缺失时提供刷新或设置入口。

错误先说明发生了什么和用户可以做什么，再提供安全的机器错误码与结构化详情。
已知原因使用统一中文词表，未知码保留原值并说明尚未识别；不展示未经处理的 stderr。
当前错误不藏在默认关闭的详情中，也不让 Tooltip 成为唯一恢复说明。

状态语义遵守[子系统状态与失败行为](../../docs/subsystems/studio-panel.md#关键状态转换)。
任务结束、证据完整、封存和核验各自表达，不合并为一个绿色“成功”。
显示或复制内容仍遵守该参考的安全约束。

## 测量、进度与图表

数据层的 `null` 与 UI 文案分开：缺少测量显示“缺测”及原因；未知总量显示“总量未知”；
未配置显示“未配置”；无活动进程显示“未启动／无活动进程”；不适用显示“不适用”。
原始诊断展示可保留 `null`，但它不作为主要指标值。此规则不改变序列化契约。

测量单位在值旁或列标题中明确标注。字节存储值与 MiB/GiB 展示换算明确，
`1 MiB = 1,048,576 bytes`，`1 GiB = 1,073,741,824 bytes`。
速率沿用 `formatRate` 的 bytes/s、KiB/s、MiB/s 分档；详情可给原始值。
正文避免科学计数法和无意义的小数长串。

确定进度只使用可信分母和有限的 0–1 值，并说明分母，例如冻结选中题集合、续测子集或六个准备阶段。
总量未知使用 `components.Progress(c, -1)` 或 Spinner，不传 `NaN`，不推算百分比或剩余时间。
活动条、进度条和无文字 Spinner 均有 `Label`。阶段进度不得被解释为样本完成率。

资源曲线用三个 `components.chart.Line` 图呈现：内存（可用内存与服务 RSS，共用 GiB 刻度）、
服务 CPU %、温度 °C，各自独立刻度。横轴是等距样本分类轴——按 UTC 采样顺序排列，实际时间见采样值——
不是按真实时间间隔的比例轴。缺测以 `NaN` 保留断点，不补零。
曲线保留缺失采样断点；轴、图例、单位、时间基准和独立尺度直接可见。
颜色之外提供名称、样本描述与原始采样（UTC 与 bytes）数据表，并保留悬停与键盘选择样本。
不同尺度的曲线不比较绝对高度。无样本时给等待或缺测原因，不能画零值来填空。

## 无障碍与原生体验

标题有角色和层级；无文字控件、表格、列表和图表有名称。`ListState.Label` 命名行，
容器 `.Label(...)` 命名整个表格，两者不能互相替代。字段说明与错误关联输入。
Tooltip 只补充信息，必要条件和缺测原因同时有可见文字。

键盘应能完成导航、编辑、选择来源、打开报告、查看详情和取消任务。
焦点环保持可见，表格支持方向键选择和约定的 Enter 提交；不同页面不复用错位选择。
长列表按稳定 ID 保留选择，页切换后验证焦点不会落在不可见内容。

保留主题对 `HighContrast`、`TextScale` 和 `ReduceMotion` 的响应。
自定义绘制或动画需单独核验，不把主题支持等同于每个组件已经遵守偏好。
辅助技术验收使用平台真实工具；测试中的标签查找不能替代 VoiceOver、Narrator 或 Orca。

## 报告视图

报告在主窗口内容区显示，沿用 onevra Shell 的主题与组件规则，提供返回列表和读取失败重试。
按模型标题、报告与题包副标题、返回按钮、四张指标卡、各类任务表现、模型与机器、逐题答案、数据来源排列。
指标卡分别显示答案通过数、请求完成率、完成请求中位耗时、服务采样峰值 RSS；窄窗口或放大文字时纵向排列。
字段映射与缺测规则集中在[子系统参考](../../docs/subsystems/studio-panel.md#运行路径)，不重算分数。
多次运行使用选择器逐次查看，不合并成绩。分类和逐题表格铺满卡片，内容过宽或超过八行时可滚动。
单个索引无法读取时保留其他列表项，打开后显示无法读取。没有加载 `report.html` 的控件。
CLI 仍生成离线 HTML；Studio 不修改历史报告文件。原生视图验收不等于 HTML 离线渲染验收。

## 验收

每项检查记录平台、源码版本、场景、操作、实际结果；不适用或无法验证要说明原因。
基准窗口 1120 × 800，压力窗口 800 × 600，宽窗口 1440 × 900；它们是项目检查点，
不是已发布的最小尺寸承诺。若平台最小尺寸阻止某检查，记录实际限制和最小可用尺寸。

1. 六个主页面与详情分别检查浅色、深色；高对比度、文字缩放 1.5/2.0 和减少动态效果另列结果。
2. 使用长路径、长模型名、多条任务、100 个报告来源、缺测和错误 fixture 检查布局。
3. 每页覆盖首载、空态、成功内容、错误、操作进行中；实时页面追加完成、失败与取消状态。
4. 用键盘走通页切换、字段纠错、表格选择、返回、取消和报告打开；检查标题、名称及公告。
5. 在原生窗口验证滚动、缩放、焦点与平台辅助技术；报告视图另测索引读取失败、空延迟与返回列表。
6. 使用 fixture 执行软件检查；未经任务授权不下载真实模型、不启动模型服务或发送推理请求。

从 `studio/` 执行已有页面检查：

```sh
mise exec -- env GOTOOLCHAIN=go1.27.2 GOPROXY=https://goproxy.cn,direct CGO_ENABLED=0 go test ./internal/pages -count=1
```

改变页面行为后执行 [Studio README 的检查](../README.md#verification-boundaries)，
补充真实失败路径的回归。纯规范变更检查链接、命令与差异即可。
测试通过、导出 PNG 和真机验收是不同证据；当前覆盖见[本次审查](design-system-audit.md)。
