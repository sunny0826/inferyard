# Studio Design System

本规范面向 Studio 页面设计、开发与验收。适用六个主页面、运行详情和主窗口内报告视图。
以 onevra v0.2026.17 为组件基线，它构建在 MyGo v0.7.4 之上；CLI 生成的报告正文继续遵守
[报告契约](../../cli/docs/contracts/report-contract.md)。

本规范由模型页已有视觉规格扩展为全局规则。本文是目标规范，不代表现有页面已经全部满足；
当前差距见[页面审查](design-system-audit.md)，未完成工作集中在
[backlog](../../cli/docs/backlog.md#inferyard-studio-后续工作)。

## 页面结构

用户进入一页时，先看到当前状态与下一步，再看到可操作内容和解释依据。
除普通任务页外，每页有一个一级标题；普通任务页直接展示说明、进度和当前阶段操作，
不显示额外的页顶标题，读屏进入该页时播报「任务」。卡片标题为二级标题，卡片内部独立分区为三级标题。
标题除了字号和字重，还须设置 `Role(ui.RoleHeading).Level(...)`。

主窗口使用 onevra `shells/sidebar.Shell`：可折叠、可拖拽调宽的侧栏，配浮动 header 与内容区；
侧栏默认 205 DIP 宽，折叠与宽度选择在会话内保持（跨折叠与页面切换）；窗口几何经 StateKey 跨会话恢复。顶部不提供通用“刷新”按钮；
右上角用引擎、任务图标显示状态，活动下载有独立图标。引擎状态用 `lucide.Server`
并与「设备」导航的 `lucide.Cpu` 区分，可见文字带主语（如「引擎 · 已停止」）；
活动图标呼吸动效遵循 ReduceMotion；后台刷新不改变活动状态。图标带读屏名称，
点击或 Enter 展开面板，Escape 或点击外部关闭；面板不再由指针悬停打开，避免遮挡页面右上角操作。
「任务队列」面板提供「查看当前任务」、「下载中」面板提供「前往下载页」直达对应页面。
引擎状态与启停规则见 [页面参考](pages.md)。
侧栏上方「新任务」与首个导航项「任务」分工固定：工作区、结果目录和模型目录三个路径均未写入设置时，空启动打开任务页的环境准备；
任一路径已保存后，空启动打开报告。「新任务」在所有状态下保持同宽同位置的整宽次要按钮样式，
不改成危险色，也不在 205 DIP 侧栏内展开确认——那样会把导航项挤下去；
环境未齐、有在途工作（含引擎启动中/停止中）或已停在任务准备页时，入口禁用并以悬停提示说明原因与去处（环境准备或取消在任务页完成），
导航栈位置始终不变；绑定、运行或报告失败且没有在途工作时保持可用，一次点击放弃该轮并回到模型与引擎选择。「任务」只切到当前任务页，不重置、不取消、不弹确认。
侧栏保持任务、报告、模型、下载、设备、设置的顺序，用 onevra `components.Sidebar`/
`components.SidebarItem` 配 lucide 图标；
缺 CLI、目录或模型时仍能进入每一页。运行详情属于任务页，提供明确返回入口。
每页和详情分别保存滚动位置，刷新不把用户带回顶部；表单草稿不被后台刷新覆盖。

| 页面 | 首要内容与主操作 |
| --- | --- |
| 任务页 | 当前阶段、阻断原因与下一步；环境准备、启动、取消、续测 |
| 报告 | 顶层页签「测评报告 / 长上下文专项 / 运行历史」，默认测评报告；页签状态随页面保存（重绘与新任务不重置），切换工作区或重置模拟场景时回到默认；测评报告为卡片（模型为主标题、逐 run 质量分行、主按钮「打开报告」、另做报告折叠）；运行历史用五列紧凑表（模型/测评题集/状态/评分/开始时间），高度随行数（最多八行），有行而未选时提示可点击查看详情，身份与路径在选中详情；报告不可核验，不提供核验入口 |
| 模型 | 只读的已安装模型/引擎清单（格式、架构、大小、核验结论）与本机运行服务；组合选择只在任务页 |
| 下载 | 仅有任务时显示清单（引擎在前，取消/重试/实际目录名）；本机推荐资源紧邻下载操作，先引擎后模型；名称、大小和选择状态直接可见，自定义地址、版本校验和凭据默认折叠；其他准备方式单独折叠 |
| 设备 | 硬件快照与采集状态、行内缺测原因；刷新设备或前往设置恢复，不提供工作区设备检查和数据来源明细 |
| 设置 | 路径编辑与保存；各路径的副作用在任务页的环境准备区说明 |
| 运行详情 | 任务身份、状态、冻结分母下的进度、题目与资源；返回和取消 |

任务页有活动任务时按任务内存状态驱动，否则恢复 `progress.v2` 阶段。环境缺项合并为「准备环境」；模型或引擎缺失时显示「准备模型与引擎」和下一步入口，隐藏空选择器与六阶段进度。资源就绪后才进入设备检查与测评选择；阶段标签为准备、设备检查、配置测评、连接并核验服务、运行、报告。阶段动作区只渲染当前阶段，不显示运行历史、快速运行与任务队列卡。活动测评题集显示队列实时状态，不展示离线恢复提示；真正中断的历史运行保留恢复原因。进入运行后，模型服务收起至固定右上角；排队、运行、取消收尾及活动任务的测评题集切换期间不展开服务卡。运行结束后的恢复操作见[子系统参考](../../docs/subsystems/studio-panel.md#运行路径)。新任务等待在途连接或运行取消收尾后回到共用引擎和模型选择；完成步骤展示本轮各次运行的成绩摘要，提供主按钮「查看报告」（直接打开本次报告）与「再次测评」，不显示输出路径或生成成功文字。

任务页是组合选择的唯一入口；模型页只读列出已安装模型与引擎及其核验结论，并提供只读服务卡，不再出现选择框、组合状态或「用这个组合新开任务」。空清单显示「到下载页」；遗留引擎仅警告，恢复操作留在任务页。
下载任务集中在下载页。其他页面可以折叠低频诊断信息，但当前阻断原因、
失败恢复动作、必要输入和关键缺测原因必须直接可见。原始字段树只用于诊断或原始参数。

推荐资源按当前 OS 与架构筛选，跨平台资产共用条目；选择状态从 URL 派生。具体筛选、手工输入与参考资源约束见[下载运行路径](../../docs/subsystems/studio-panel/runtime.md)。

## 表单与操作

输入均通过 `ui.Field` 关联标签，标签说明用户需要输入什么。必需项、默认来源、格式和
成对条件用字段说明表达；占位符不能代替标签。错误用字段 `Error` 或控件 `Error`
关联到具体输入，并在页内保留整体失败结果。服务器和 CLI 校验仍然有效。

每个操作组有明确主操作。页面同时存在安装、保存、初始化等独立流程时，每组最多一个
主按钮，并按当前下一步突出其中最相关的一组。设置页仅路径区的“保存”使用主按钮，下载目录名操作使用普通按钮。按钮用动词与对象命名，例如“保存”
“准备环境”“开始测评”“请求取消”；这些操作不可合并为含糊的“确定”。

禁用状态旁说明缺少的条件。提交后保留输入，阻止重复执行并显示正在处理的对象。
取消请求发出后显示“取消中／等待收尾”，直到终态到达；不立即显示“已取消”。
普通可恢复操作不增加确认框；单测评题集等契约要求的显式选择仍保留。

成功 Toast 使用 MyGo 自带公告能力。Toast 固定在窗口顶部居中，位置由
`pageShellOptions` 显式指定为 `components.ToastTop`；不依赖 Onevra 的默认值，因为
v0.2026.13 的升级把默认位置从底部改到了顶部。异步错误、阻断或页面变化没有 Toast
时，须提供一次性辅助技术公告或合理的焦点转移；不能在每次渲染或每个采样点重复播报。
刷新不抢焦点；关闭对话框或返回列表后恢复到合理位置。

## 状态、空态与错误

首次读取、后台刷新、无数据和读取失败分别表示。刷新可保留已有内容并标明正在更新；
失败时保留错误和恢复入口，不能同时暗示仍在正常加载。

空态包含对象、原因或准备条件、下一步入口。尚无报告时指向新任务或「从历史运行另做报告」；
没有来源 run 时指向启动测评；设备快照缺失时提供刷新或设置入口。

错误先说明发生了什么和用户可以做什么，再提供安全的机器错误码与结构化详情。
已知原因使用统一中文词表，未知码保留原值并说明尚未识别；不展示未经处理的 stderr。
当前错误不藏在默认关闭的详情中，也不让 Tooltip 成为唯一恢复说明。

状态语义遵守[子系统状态与失败行为](../../docs/subsystems/studio-panel.md#关键状态转换)。
任务结束、证据完整、封存和核验各自表达，不合并为一个绿色“成功”。
显示或复制内容仍遵守该参考的安全约束。

## 验收

每项检查记录平台、源码版本、场景、操作、实际结果；不适用或无法验证要说明原因。
基准窗口 1120 × 800，压力窗口 800 × 600，宽窗口 1440 × 900；它们是项目检查点，
不是已发布的最小尺寸承诺。若平台最小尺寸阻止某检查，记录实际限制和最小可用尺寸。

1. 六个主页面与详情分别检查浅色、深色；高对比度、文字缩放 1.5/2.0 和减少动态效果另列结果。
2. 使用长路径、长模型名、多条任务、100 个报告来源、缺测和错误 fixture 检查布局。
3. 每页覆盖首载、空态、成功内容、错误、操作进行中；实时页面追加完成、失败与取消状态。
4. 用键盘走通页切换、字段纠错、表格选择、返回、取消和报告打开；检查标题、名称及公告。
5. 在原生窗口验证滚动、缩放、焦点与平台辅助技术；报告视图另测索引读取失败、空延迟与返回列表。
6. 使用 fixture 执行软件检查；未经任务授权不下载真实模型、不启动模型服务或发送推理请求。

从 `studio/` 执行已有页面检查：

```sh
mise exec -- env GOTOOLCHAIN=go1.27.3 GOPROXY=https://goproxy.cn,direct CGO_ENABLED=0 go test ./internal/pages -count=1
```

人工调整样式时使用 [UI debug preview](../README.md#ui-debug-preview)：
`mise exec -- go run -tags ui_debug . --debug-ui` 打开同一套原生页面。用页面按钮连续完成准备环境、下载、运行、取消、重试和打开报告；进度自动推进。侧栏场景用于设置检查起点，「重置场景」清空本次模拟改动。
调试场景检查用 `mise exec -- go test -tags ui_debug ./internal/pages`；普通构建与正式包不包含预览入口。
固定 fixture 覆盖常用任务、报告、空态、错误与缺测，不等于上述验收矩阵已全部覆盖；
实际操作隔离规则见[子系统参考](../../docs/subsystems/studio-panel.md#ui-调试预览)。

改变页面行为后执行 [Studio README 的检查](../README.md#verification-boundaries)，
补充真实失败路径的回归。纯规范变更检查链接、命令与差异即可。
测试通过、导出 PNG 和真机验收是不同证据；当前覆盖见[本次审查](design-system-audit.md)。
