# Studio 本地引擎

Studio 注册已有安装声明，CLI 负责安装、候选与绑定语义。正式配置与运行边界见
[本地引擎契约](../../../cli/docs/contracts/local-engines.md)，命令和查询字段见
[CLI 参考](../../../cli/docs/cli-reference/local-engines.md)。当前本地 profile 限定 macOS Metal；
引擎核验通过不等于完整模型验收通过。

## 资源与候选

设置页登记安装声明的绝对路径，可移除或重新核验；仅路径进入 `engine_installations`，
不导入环境变量、启动参数或凭据。`engine check --installation` 返回
`local-engine-check.v2`；核验缓存绑定声明文件字节摘要，成功结果另携带规范声明摘要。
修改声明后原核验与原候选不能继续代表当前选择。旧查询版本明确拒绝，须用配套 CLI 重新查询。

清单同时保留原有二进制引擎和安装声明；名称映射到实际路径由 core 持有。
模型目录扫描有深度与数量边界，排除虚拟环境和越界符号链接；GGUF 与目录模型明确标注。
llama-cpp、LM Studio 接受 GGUF，MLX、vLLM、SGLang 接受目录模型；任务表单拒绝不匹配的选择。
本地路径不依赖旧 GGUF 设备推荐；长上下文专项尚未支持该 profile，页面与服务准入均明确拒绝。

`PrepareLocalCandidates` 为所选题包创建新的候选目录，经 CLI `config create` 冻结。
SGLang 每个候选使用新的工作目录、metrics 目录与运行 ID，不改写注册的安装声明。
core 在本窗口内记录派生声明与注册声明的关系；重启后缺少该关系时不能冒认旧候选属于当前选择。
候选读取与启动统一调用 `config describe`：本地为 `local-engine-description.v2`，
原有二进制路径为 `engine-description.v1`。Go 不自行解释 TOML 启动参数。
候选归属核验在后台执行，结果绑定当前选择，过期响应不回写页面。

## 串行执行与所有权

`StartCandidateRuns` 将一至两个同家族、同模型且题包不同的候选加入现有串行队列。
每个任务依次准备服务、绑定、执行；前一题包不是完整成功时，后续题包拒绝开始。
`PreparationStage` 表示切换、启动、绑定或等待外部服务，`AwaitingService` 控制绑定表单。

直接服务家族由 Studio 按 CLI 描述的 argv、cwd 和受控环境启动；新题包先停止旧自有服务，
确认已退出，再启动新服务并通过 CLI 绑定。就绪探测使用 `/v1/models`。
Unix 本地服务使用独立进程组；所有权记录保存根进程及已观察 worker 的 PID/start ticks，
仅在原根进程或已记录成员身份仍能锚定该组时接纳新成员。停止前逐进程复核身份，
SIGTERM 超时才升级 kill；不能确认归属时保留遗留记录并阻断下一题包。
该机制跟踪独立进程组及已记录成员，未声称接管无法观察到的脱组进程。
原有二进制引擎保留原生命周期；所有权文件更新与删除沿用跨进程锁及内容身份比对。

LM Studio 使用操作者提供的已加载服务 PID 和 endpoint。Studio 不执行 lms 启停或加载，
不取得该后台所有权。首题包可使用表单输入；下一题包与手动重试等待操作者替换服务后重新绑定。
已用于本窗口本地运行的 PID/start ticks 不能再次使用；CLI 仍核验旧 scope 的进程树退出、
实际 listener、模型与完整身份。无效输入不能消耗等待入口，不能仅凭 endpoint 相同沿用旧服务。

取消先中断 CLI 并等待其返回，再清理本次自启服务；LM 后台不受停止动作影响。
绑定或启动失败会清理已启动服务；失败不自动重试。
手动「重试未完成的题包」保留本任务成功的 run，仅为未完成题包创建新运行；直接服务重建候选，
LM 保留冻结候选并等待新服务。全部选中题包完整成功后才生成报告，来源仅为本任务各题包的成功 run。
取消、硬件停止和 CLI dirty 标记仍按原契约处理，不自动清标记或降低停止阈值。

## 验证边界

`local_runs_test.go` 使用实际 core 队列和测试进程验证四个直接家族的逐题包服务替换、
绑定失败阻断、取消清理和外部服务等待。它不是四种真实引擎的运行证据。
`preview_local_parity_test.go` 将实际页面编排和 core.Service（CLI 边界注入受控响应）
与独立内存模拟分别对照明确预期，再比较双题包、第二次绑定失败后的手动重试、等待取消、
旧服务拒绝及报告范围；隔离的故意错误证明一致性断言会失败。
正常取消按钮另对照实际 core 队列与测试服务的停止结果、两题包取消和无报告；
新增回归先复现模拟服务仍 running 的分歧，修复后通过。绑定期间 PID/start ticks 变化同样先复现再拒绝。
原生 XCUITest 的目录模型双题包与 LM 重绑场景另验，不能用页面内存回归代替。
当前验收进度只记在[backlog](../../../cli/docs/backlog/model-engine.md#本地五引擎正式适配)。
