## 维护参考

当变更改变了已记录的职责、接口、状态转换、运行路径、兼容规则或失败行为时，在同一个 PR 更新所属参考。保持这些契约不变的内部重构不要求改动散文。

每条事实只保留在一个参考中，Agent 约定与其他页面链接到它。链接到源码文件和具名符号，而不是复制经常变化的实现细节。解释签名本身表达不了的字段含义与约束。

新参考必须包含：职责与边界、事实源、主要运行路径、状态转换、关键约束和现有验证命令；相关时包含失败与兼容行为。当前行为与提议变更分开记录；提议属于 issue 或 PR，不进入参考。

## 描述 PR 的语义变化

对每个受影响的子系统，解释可观察的变化及其触发条件和前后行为。相关时包括接口、状态、兼容性和失败行为的变化。链接受影响的参考、实现和验证证据。重构保持已记录行为时要声明。

例如，一个改变封存顺序的 PR 应说明哪个证据布局版本和写入阶段触发新顺序、前后由哪个实现处理封存，以及哪个测试演练该转换。

这是作者提供的解释，审查者对照 diff 和周边代码核实；它不是自动证明的兼容性结论。

## 审查变更

1. 识别受影响的子系统和实际运行路径，包括涉及的包归属。
2. 对照 base 与 head 实现比较声明的前后行为，追踪改动行之外的调用者与状态转换。
3. 检查变化的契约已出现在所属参考中，且源码链接仍可解析。
4. 检查引用的测试或运行证据确实演练了声明的行为，报告未运行的检查。

仅文档更新不能证明实现。行为变化仍需要现有测试和运行证据。
