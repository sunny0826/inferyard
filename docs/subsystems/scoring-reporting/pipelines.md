# 运行路径

本页是[评分、比较与报告](../scoring-reporting.md) 的子文档，收录「运行路径」的正文；内容不变，入口保留原节标题与锚点。

1. **执行期评分**（入口在运行时）：`runner` / `request_execution` 构造 `ScoringContext`，`prepare` 深拷贝并校验冻结题目（structured 类预建 `Draft202012Validator`），协议完成后对答案调用 `score` 得到 score 文档并随日志落盘；终态保存与评分保存分离。异常或不完整输入产生 `unscorable` 结果，不撤销执行终态。该环节跨子系统，见[运行时执行与引擎适配](../runtime-execution.md)。
2. **离线归约**：证据账本 `read_trial` 重建 trial 视图后，`build_observations` 以质量（`summarize_quality`）与计时（`request_timing`、最近秩分位）归约生成 `summary.metric_observations`，每条观测绑定证据文件哈希；`repetition_metrics` 与 `summarize_windows` 处理多轮与分窗场景。账本与封存属于[证据、封存与离线读取](../evidence-storage.md)。
3. **报告生成**：`report` 命令经 `application/dispatch.py` 分派到 [`application/reporting.py`](../../../cli/src/inferyard/application/reporting.py)，后者调用 [`reporting/studio_report.py`](../../../cli/src/inferyard/reporting/studio_report.py) 的 `write_studio_report`，逐 run 归约（恰好两个 run 时自动做并列比较并拒绝重复 run）、来源路径转为相对定位，原子写入 `studio.json`（`studio-report.v1`，`schema_version = 3`）。产物目录以 `0o700` 新建，且不得位于原始证据内部（`new_output` 检查）。
4. **报告不可核验**：报告改为纯 JSON 派生投影后不再是核验产物：`verify --path` 识别到报告目录（`studio.json` 或旧 `index.json`/`report.html`）固定退出 4（`studio_report_not_verifiable`），旧格式报告退出 2（`unsupported_format`）。报告可由来源 run 重建，核验继续覆盖原始 run 本身。来源单独移动时用 `--source-root OLD=NEW` 显式映射，保存文件不变（见 [reports.md](../../../cli/docs/reports.md)）。
5. **比较产物**：`compare` 命令加载两份 `comparison_input`（核验指标引用与 manifest 身份），`build_comparison` 要求比较格式为 5、性能证据两侧同时提供或同时缺失且目标 manifest 未变，`compare_trials` 逐字段产出 `conditions`、`blockers` 与分维度 `eligibility`；`compare-check` 离线重算并核验。
   `compare-engines --plan --batch` 先经 [`runtime/comparison_v2_read.py`](../../../cli/src/inferyard/runtime/comparison_v2_read.py) 读取并核验完整计划、batch、交接链与共享停止（判定与分组留在 [`analysis/engine_comparison_v2.py`](../../../cli/src/inferyard/analysis/engine_comparison_v2.py)），再按题包复用六块判定；[`reporting/engine_comparison_v2_report.py`](../../../cli/src/inferyard/reporting/engine_comparison_v2_report.py) 写入单文件 `engine-comparison.json`（`engine-comparison.v2`，`format_version = 2`）。`verify` 按 result 的 definition 与 format_version 区分并从 plan/batch 重算比对；旧 v1 与旧版 v2 产物以 `unsupported_format` 拒绝。规则见[跨引擎比较契约](../../../cli/docs/contracts/engine-comparison.md)。
6. **重评分**：`rescore` 命令以 `--scorer` 选择评分版本、`--reason` 为必填（非空且 ≤500 字符），`build_rescore` 只对 `completed` 请求重打分并生成新的 `analysis_id`；父分析以 `parent_analysis_id` 绑定，谱系通过 `parent-lineage.json` 递归重放（深度上限 16）。`rescore-check` 从来源证据完整重建并逐字节比对。
7. **导出与公开发布**：`export` 从已封存 run 生成 `analysis.json`、`metrics.csv`、`metrics.md`（源 manifest 未封存时拒绝），或从既有分析目录导出；`export-check` 核验。`public-package` 经 `project_metrics` 只发布白名单内的文本，其余字符串以 SHA-256 指纹代替并标 `redacted`。
8. **重复实验报告**：`repeat-summary` 命令对同一计划的多个 run 写出重复摘要（`write_repetition_summary`），逐轮值、有效样本与范围只描述已观测轮次，不拼装未完成的轮次；`repeat-check` 离线核验。
