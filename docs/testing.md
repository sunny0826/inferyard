# 测试与检查的保留标准

仅保留能验证产品或逻辑假设的测试，以及正确打包、安装、发布所需的检查。假设必须说明具体条件和可观察结果：破坏它，会让用户流程、证据或结论出错。测试名称、所在目录、单元或端到端分类都不是保留理由。

[逐项裁决索引](testing-decisions.json)绑定清理前的 Git 提交，按审查分组、原始来源文件导航到每个测试的去留、理由及必要的改名或迁移映射；记录中的路径均相对仓库根目录。计数按函数而非参数展开后的测试节点。文件名清单之外的显式执行入口单独列出，避免混入原始基线。

## 判断方法

阅读测试体、参数和子场景，回答：它会阻止哪一种具体产品错误？若只能回答“实现符合当前代码”，删除。重复覆盖同一条件和结果、且没有独立故障路径的测试也删除；不要通过改名或补一句泛泛的产品理由保留。

有价值的假设例如：

- 错误答案和评分失败仍在冻结分母内，否则质量分会虚高。
- 取消后停止派发，未排空的服务保持阻断，否则下一轮测评会混入旧请求。
- 报告缺测显示缺失和原因，不能变成零，否则用户会误判性能。
- 报告只包含本次任务的来源，配置或身份不一致时拒绝比较，否则结论会归错模型。
- 重建、重试和恢复保留原证据，失败时不覆盖历史或误停其他进程。
- 安装后的 CLI 能从发行包读取资源，正式 Studio 不携带可执行的调试入口。

直接检查评分、单位转换或状态转换的单元测试也可以证明这些假设。使用 mock 本身不构成删除理由；关键在于断言是否验证结果或必要的副作用边界，而非复述 mock 的设置。

## 删除范围

- 源码文本、AST 形状、函数拆分、私有对象布局和内部路由方式。
- 不对应产品预算的读取次数、调用次数、缓存命中和固定调度步数。
- 固定色值、像素哈希、控件类型和布局树等实现快照。真实控件能否操作、关键内容能否读到仍属于产品行为。
- 相同正常路径的重复测试、标准库自身行为的复测、只验证测试夹具如何实现的测试。
- 格式、import 排序和语法新旧偏好等代码风格门禁。

混合测试只保留有价值的断言。预期应来自明确规则或手算结果，不能让待测实现计算自己的正确答案；两条路径分别满足同一独立预期后，无需再重复比较整体相等。

删除测试后同步清理独占 helper、fixture、失效引用和执行入口；其他保留测试或打包流程仍引用的 helper 必须继续存在。

## 保留的检查

Ruff 仅阻断语法、非法表达式或控制流、未定义名称，以及共享可变默认值、`finally` 吞掉退出、循环闭包错误绑定等运行缺陷。具体规则由 [CLI 配置](../cli/pyproject.toml) 定义，不运行格式检查门禁。

Go 编译和测试继续校验类型及可执行性。Schema、指标目录和社区资源检查验证发行内容与活动定义一致；wheel/sdist、依赖约束、安装后命令、发布候选摘要与来源、Studio release 标签及跨平台打包检查继续保留。目标引擎环境的 Python 语法兼容检查属于运行保障，不等同于约束源码形状。

原生 UI 测试证明真实窗口中的操作和呈现；模拟、CLI 与假引擎边界测试、真机模型执行各自提供不同证据。保留一层不能宣称其他层已经通过。运行命令与平台边界仍见 [CLI 贡献指南](../cli/CONTRIBUTING.md#changes-and-verification)、[Studio README](../studio/README.md#verification-boundaries) 和 [原生 UI 测试说明](../studio/tests/ui/README.md)。
