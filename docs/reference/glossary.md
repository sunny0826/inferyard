## 1. 评测对象与范围

| 术语及别名                       | 含义                                                                                   | 本项目使用边界                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| AI / 人工智能；Local AI / 本地 AI | AI 是人工智能的统称；本地 AI 指主要计算在用户控制的本地设备运行。                         | 本地模型并不保证检索、工具和其他组件全部离线。                  |
| LM / LLM                         | Language Model / Large Language Model，语言模型/大语言模型。                           | 本表主体是生成文本的模型及其运行系统。                          |
| benchmark / 基准测评             | 用固定任务、规则和指标观察、比较系统。                                                 | 不仅是一组题或一个总分；版本和执行协议同样重要。                |
| 被测系统 / SUT                   | System Under Test，实际接受测试的完整对象。                                            | 模型、设备、引擎、配置及必要辅助组件的边界需写清。              |
| 测评单位 / 运行方案              | 一组明确的设备、模型变体、引擎配置和任务。                                             | 同名模型换量化、模板或引擎后可能是另一方案。                    |
| 稳定性 / 可靠性 / 鲁棒性         | 稳定性关注持续或重复运行；可靠性关注按要求成功；鲁棒性关注输入扰动或环境变化后仍有效。 | 波动、故障和质量变化分别量化，不能由短测推断长期可靠。          |
| 能力 / 质量；性能                | 能力、质量关注是否做对；性能关注耗时、吞吐等运行表现。                                 | 请求返回成功不表示答案正确。                                    |
| 兼容性 / 运行门槛                | 设备和软件组合能否加载、生成及提供指定功能。                                           | 功能冒烟通过不等于正式能力验收通过。                            |
| 基础 / 条件 / 核验               | 表中三类适用标签：共用评测问题、依赖特定条件、资料采集/计算/审计。                     | 不是执行优先级或得分；基础项也可能缺测。                        |
| 必测项 / 扩展项 / 范围外         | 测前规定的必须完成、按需求增加、不参与本次结论的项目。                                 | 不能因结果差而事后移出必测范围。                                |
| 未测 / 不支持 / 不适用 / 不可测  | 分别是尚未运行、缺少所需功能、不在范围、无法取得该指标。                               | 四者都不能用同一个 0 替代；不支持必需能力时仍可判不合格。         |
| 运行完成 / 质量通过 / 实验无效   | 分别描述正常结束、答案通过验收、测评基础设施等使实验无效。                             | 属于不同层次；正常完成但质量不通过很常见。                      |
| 可行性 / 普遍性                  | 可行性是有实际执行路径；普遍性是问题和定义能跨方案使用。                               | 有设计路径不等于已实测；普遍不等于所有平台用同一工具。          |
| 关联程度 / 权重 / 实施优先级     | 分别表示贴近用户决策的程度、聚合分数的比例、先实施什么。                               | 本表只确定第一项，不能由排名推导另外两项。                      |
| 模型成绩 / 系统成绩              | 前者针对声明条件下的模型；后者包含框架、工具及环境协作。                               | Agent、外接 OCR 等结果应说明系统边界。                          |
| 基线 / 参照 / 对照组             | 用来比较变化的原始配置或参考结果。                                                     | 不同设备的参考质量不能作为目标设备速度基线。                    |
| 质量底线 / 验收阈值 / 门槛       | 事先规定的最低质量、最高延迟或资源限制。                                               | 未设阈值时只能报告观测值，不能凭印象说达标。                    |
| 能力边界 / 容量边界              | 分别是仍能做好的任务范围、资源或接口可容纳的范围。                                     | 能装入输入与能理解输入是两件事。                                |
| 扩展范围：embedding / reranker   | embedding 把内容映射成向量；reranker 对候选结果重新排序。                                | 独立模型需增加检索、排序等专用评测，不由当前 199 项宣称完整覆盖。 |

## 2. 模型与输入输出

| 术语及别名                               | 含义                                                                                       | 本项目使用边界                                                                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 基座模型 / 基础模型                      | 比较所基于的原始模型；通常尚未针对对话指令专门调整。                                       | 量化比较须锁定同一基座版本。                                                                                                                  |
| 指令模型 / 推理模型 / 多模态模型         | 分别侧重遵循指令、推理过程或处理多种输入模态的模型类型。                                   | 模型卡的定位不等于实测能力保证。                                                                                                              |
| 模型卡 / README                          | 模型卡说明模型用途、结构、训练、限制及许可；README 是项目或仓库的入门说明，可能包含模型卡。 | 是来源资料；需与实际产物及功能核对，README 不保证包含完整模型信息。                                                                            |
| 权重 / 参数 / 张量                       | 权重是模型学习得到的数值；参数量计数这些数值；张量是存放数值的多维数组。                   | 文件字节数不等于参数个数。                                                                                                                    |
| 稠密模型 / MoE                           | 稠密模型通常让主体参数参与计算；MoE 是 Mixture of Experts，按输入路由选择部分专家。          | 总参数、每 token 激活参数和驻留参数须分开。                                                                                                     |
| 专家 / 路由 / 激活参数                   | 专家是可选子网络；路由决定调用哪些专家；激活参数是一次计算实际参与的参数。                 | 少量激活不代表其余专家无需存储。                                                                                                              |
| 架构 / 自回归 / 混合架构                 | 架构是模型计算结构；自回归按既有内容逐步生成；混合架构结合多种结构。                       | 非自回归或混合结构不必具备传统同义的 prefill/decode/KV 指标。                                                                                   |
| 精度 / 高精度基线                        | 表示数值的位宽和表示方式；高精度基线通常保留较少数值压缩。                                 | 更高位宽不保证每题更好；基线也需核实版本与模板。                                                                                              |
| 量化 / 权重量化                          | 用较低精度或编码方式表示权重以减少占用或计算成本。                                         | 实际收益取决于引擎、硬件及算法。                                                                                                              |
| Q4 / 量化变体                            | Q4 常用于约 4 位权重量化的命名；变体还包括算法、分组和元数据。                                | 不是跨格式统一标准；两个 Q4 文件不必同精度、同大小。                                                                                            |
| 校准数据 / 校准集                        | 某些量化方法用来估计数值分布、选择缩放等参数的数据。                                       | 与“概率校准”不同；可能影响特定能力及污染风险。                                                                                                |
| token / native token                     | tokenizer 划分出的模型处理单位；native 表示该模型自己的划分。                                | 一个 token 不等于一个汉字、一个词或一个字节。                                                                                                   |
| tokenizer / 分词器 / tokenization        | tokenizer 是文本与 token ID 之间的编码、解码规则及词表；tokenization 指分词编码过程。          | 模型、版本、特殊 token 配置都要固定。                                                                                                           |
| 重分词 / 可见文本 token 估计               | 将输出文本再次交给 tokenizer 计数。                                                          | 不保证恢复真实生成序列，也不含不可见思考等内容。                                                                                              |
| Unicode 码点 / 字符                       | Unicode 码点是给字符编码的单位。                                                            | 本项目字符计数默认码点；一个可见字形可能由多个码点组成。                                                                                      |
| prompt / 提示词；系统提示词              | prompt 是输入给模型的指令和内容；系统提示词是其中高层规则部分。                             | 要保存版本及实际渲染结果。                                                                                                                    |
| 聊天模板 / role / 渲染输入               | 模板将多角色对话转换成模型格式；role 标记角色；渲染输入是模板应用后的实际内容。             | role 事件等协议元数据不能算首个生成内容。                                                                                                      |
| 上下文 / 上下文窗口                      | 模型处理当前请求可利用的信息及其长度约束。                                                 | 输入、输出、模板和媒体是否共享容量取决于架构和实现。                                                                                          |
| 输出预算 / 思考预算                      | 对生成长度、时间或推理过程设置的限制。                                                     | 请求的值不一定被后端执行，应核实生效值。                                                                                                    |
| 思考通道 / 答案通道 / 隐藏思考           | 协议中区分推理内容与最终答案的字段；隐藏思考不向客户端开放。                               | 不可见就记未知；不以思考长度衡量质量。                                                                                                        |
| 采样 / sampling / temperature / 随机种子 | 采样是从候选输出选择 token；temperature 调节概率分布；种子初始化随机过程。                   | temperature=0 或相同种子不保证所有硬件逐字一致。                                                                                               |
| 输出编码 / 乱码                          | 字节与文字之间的表示规则；乱码是错误解码或无效字符等异常。                                 | 保存原始字节，区分传输/解码问题与模型生成内容本身异常。                                                                                       |
| EOS / 停止词 / 终止原因                  | EOS 为结束序列标记；停止词是触发停止的文本条件；终止原因解释为什么结束。                    | 长度上限、自然结束、取消和超时分开。                                                                                                          |
| 截断 / 静默截断                          | 因长度等限制丢弃部分输入或输出；静默截断未明确告知调用者。                                 | 定长性能目标已完成与自然回答被截断须分别判断。                                                                                                |
| cache / 缓存 / KV cache                  | cache 是复用已计算数据；KV 是注意力机制中键和值的缓存。                                      | KV 不是全部内存；有些架构无传统 KV，增长也不必线性。                                                                                            |
| KV 量化 / KV 精度                          | 压缩缓存中的键值表示。                                                                     | 与权重量化分开控制与评分。                                                                                                                    |
| 滑动窗口                                 | 只在限定近期范围保留或使用部分历史信息的机制。                                             | 可能改变缓存增长，不能由标称总长度推断内存。                                                                                                  |
| prompt cache / 前缀缓存                  | 对重复输入前缀复用已有计算或状态。                                                         | 缓存命中加速不能归为纯算力提升。                                                                                                              |
| 命中 / 未命中 / 缓存驱逐                 | 分别是复用成功、需重新处理、缓存内容被移除。                                               | 需要日志证据；仅变快不证明命中。                                                                                                              |
| 检索 / 多跳关联 / 单针检索               | 检索寻找信息；多跳把多条信息依次关联；单针检索是在大量材料中找一个预埋目标。               | 找到单个目标不能代表综合理解长文本；检索索引也可能是外部组件。                                                                                |
| 推测解码 / 草稿 / 接受率                 | 先产生候选，再由目标模型验证；接受率描述草稿被采纳的比例。                                 | 草稿可能来自另一模型或其他机制；分母按引擎协议公开。                                                                                          |
| 上下文压缩                               | 用摘要、筛选等方式缩短历史或材料。                                                         | 应计压缩器本身成本和丢失信息，不只算主模型。                                                                                                  |
| loglikelihood / 对数似然                 | 对指定候选文本给出条件生成概率的对数。                                                     | 需要相应接口；让模型回答 A/B 不是等价实现。见[lm-eval 接口](https://github.com/EleutherAI/lm-evaluation-harness/blob/main/docs/model_guide.md)。 |
| generate_until                           | 生成文本直到满足停止条件的接口/任务方式。                                                  | 与对候选文本打概率分是不同评测协议。                                                                                                          |
| 模型适配器 / 额外适配器                  | 加在基座上的附加模型参数或组件。                                                           | 与连接不同软件的“接口适配器”分开记录。                                                                                                        |

## 3. 硬件与资源

| 术语及别名                              | 含义                                                                              | 本项目使用边界                                             |
| --------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| CPU / GPU / NPU；CPU-only               | CPU 是通用处理器；GPU 是图形/并行处理器；NPU 是神经网络加速器；CPU-only 只用 CPU 计算。 | 实际启用设备与安装设备可能不同。                           |
| 内存 / 显存 / 统一内存                  | 分别指主机内存、GPU 可用存储、由 CPU/GPU 等共享的内存体系。                          | 统一内存的 CPU 与 GPU 统计可能重叠，不能直接相加。             |
| 物理容量 / 可用容量 / 系统保留          | 实际安装量、当前可使用量、系统或驱动占用/预留量。                                 | 用户可运行规模依赖可用量而不只是标称容量。                 |
| RSS / 进程常驻集                        | Resident Set Size，进程当前驻留在物理内存中的页统计。                             | 不等于进程全部虚拟地址或独占内存；共享页口径依平台。       |
| 设备级 / 进程级 / 引擎级                | 对整块设备、单进程、引擎分配器分别观测资源。                                      | 三种视角覆盖不同，不能相加当总内存。                       |
| 已分配 / 保留内存 / 预留池              | 已分配用于对象；保留/预留池为后续复用提前占有空间。                               | 释放对象后保留池可能仍大，不能直接判断泄漏。               |
| 常驻占用 / 空闲基线 / 可用余量          | 分别是模型无请求时占用、声明空闲状态的资源值、剩余可用资源。                      | 空闲时模型是否驻留要注明。                                 |
| 峰值 / 采样观测峰值                     | 观测到的最大值；采样峰值仅是离散读取中最大的一次。                                | 可能漏掉短暂尖峰；与引擎高水位计数器分开。                 |
| 内存泄漏 / 缓存平台                     | 泄漏是资源未能正常释放；平台是增长后稳定在某一范围。                              | 持续增长先称疑似泄漏，需清缓存、重启等对照。               |
| OOM                                     | Out Of Memory，分配所需内存失败。                                                 | 可能表现为报错、杀进程或系统失稳；不能只搜某个错误字符串。 |
| 完整驻留 / CPU 卸载 / 磁盘卸载           | 权重/状态全部留在目标设备，或部分由 CPU 内存/磁盘承担。                             | 实际张量放置要核实，不能只看 GPU 利用率。                    |
| swap / 换页                             | 操作系统在内存和交换存储之间移动内存页。                                          | 与引擎主动卸载不同；对延迟影响可能很大。                   |
| I/O / 读写                              | Input/Output，数据在存储、网络、设备等之间的传入传出。                            | 标清是磁盘还是网络、读还是写及其单位。                     |
| 文件系统 / 挂载点 / 网络存储            | 文件系统管理文件；挂载点把存储接入路径；网络存储经网络访问。                      | 容器路径不一定反映物理磁盘位置，需追踪实际落点。           |
| 稀疏文件 / 压缩存储                     | 稀疏文件未给全部逻辑区域分配块；压缩用编码减少物理占用。                          | 逻辑大小相同，实际磁盘占用可能不同。                       |
| 文件逻辑大小 / 实际块占用               | 文件显示的内容长度与文件系统真正分配的存储空间。                                  | 稀疏、压缩、硬链接会使两者不同。                           |
| 硬链接 / 共享缓存                       | 多路径引用同一文件对象，或多个模型/应用共享下载内容。                             | 计算总占用时去重，新增安装净占用另测。                     |
| 带宽 / PCIe / GPU 互联                   | 带宽是单位时间传输量；PCIe 是设备总线；GPU 互联是设备间连接。                       | 理论规格、实际链路和微测结果分别列。                       |
| 链路代际 / 宽度 / 拓扑                  | 连接标准版本、通道数量、设备与链路的连接关系。                                    | 同型号 GPU 可能因不同连接方式有不同表现。                    |
| 模型分片 / 模型并行 / 副本并行          | 分片切开模型；模型并行协作执行同一个模型；副本并行用多个模型副本处理不同请求。    | 比较的是延迟、容量还是服务吞吐要先确定。                   |
| 同构 / 异构设备；负载不均衡             | 设备相同/不同；不均衡指部分设备承担更多工作或等待。                               | 不把异构设备数量直接代入同构扩展效率结论。                 |
| 微基准 / 带宽微测                       | 用很小且受控的操作测某个部件或阶段。                                              | 部件微测有助于诊断，不能直接代表整套 LLM 任务表现。          |
| 利用率 / 忙碌率                         | 采样窗口内资源参与工作的程度。                                                    | GPU 利用率不等于显存利用率，也不等于模型吞吐。              |
| 频率 / throttle / 降频                  | 时钟运行速率；受温度、功耗等限制而降低频率。                                      | 频率与温度相关不足以证明热降频，需限制原因证据。           |
| 热稳态 / 功耗模式                       | 温度等进入相对稳定窗口；功耗模式是设备性能与耗电控制设置。                        | 稳态条件和等待方式预先定义。                               |
| 遥测 / 传感器 / 采样率                  | 系统暴露的状态数据、测量来源、每秒读取次数。                                      | 轮询更快不代表硬件刷新更快；缺失读数不填 0。                |
| profiler / profiling / profile          | profiler 是性能诊断工具；profiling 是诊断过程；profile 也可指工具的一组运行配置。    | 诊断会有额外开销，常规成绩与诊断运行分开。                 |
| 后台负载 / 前台任务 / 显示占用          | 其他程序的计算活动、用户正在操作的任务、驱动屏幕使用的资源。                      | 会影响共享设备，需记录而非默认不存在。                     |
| OS / 操作系统；驱动 / 运行库 / 计算后端 | OS 管理资源；驱动连接设备；运行库提供计算支持；后端是引擎实际使用的实现。          | 安装了某后端不等于运行时使用了它。                         |

## 4. 性能与负载

| 术语及别名                         | 含义                                                                                           | 本项目使用边界                                                    |
| ---------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 端到端耗时 / 墙钟时间              | 在声明起止事件之间实际经过的总时间，包含执行与等待。                                           | 单请求、Agent 任务、安装流程的边界不同；与实际操作人工时区分。     |
| 单调时钟 / 时间戳 / 时钟同步       | 单调时钟适合测间隔；时间戳记录事件；同步用于对齐不同设备时钟。                                 | 不直接相减两台机器各自的单调时钟。                                |
| TTFT / 首 token 延迟                 | Time To First Token，从约定起点到首个输出单位的时间。                                          | 客户端通常看到数据块；本项目区分首内容块到达和真实 token 事件。     |
| 首内容延迟 / 首答案延迟 / 显示延迟 | 分别到首个生成内容、可辨识答案、屏幕显示的等待。                                               | 首内容可能是思考；网络到达不包含后续显示耗时。                    |
| prefill / 预填充 / 输入处理        | 为输入计算模型状态的阶段。                                                                     | 不包含所有排队/网络/初始化；没有阶段事件不能拿 TTFT 当 prefill 时间。 |
| decode / 解码 / 输出生成           | 逐步产生输出的计算阶段。                                                                       | 名称和首 token 计入方式取决于引擎；非自回归模型不一定有同义阶段。   |
| tokens/s / token/s / t/s           | 每秒处理或输出 token 的速率。                                                                    | 指明是输入、引擎生成还是客户端整请求吞吐，注明计数来源。          |
| ITL / token 间隔                    | Inter-Token Latency，相邻真实 token 事件的时间差。                                               | SSE 块间隔不一定等于 ITL。                                          |
| 数据块 / SSE / 心跳                | 块是一次交付的数据；SSE 为 Server-Sent Events 流式协议；心跳用于维持连接。                        | 一个块可能有多个 token 或没有内容；空事件不计首 token。              |
| 输出停顿 / 尾延迟                  | 长时间没有输出；延迟分布较慢的一端。                                                           | 平均速度不能说明停顿情况，P99 也需充足样本。                       |
| 中位延迟 / P50 / P90 / P95 / P99   | 相应百分位位置的延迟估计，例如 P95 描述约 95%样本不超过的值。                                     | 依赖分位数算法和样本量，不是最慢值。                              |
| 冷启动 / 热启动                    | 系统尚未准备好/已准备好时启动或请求。                                                          | 分别说明进程、权重、OS 文件缓存、前缀缓存哪一层冷/热。             |
| 预热 / 首次请求                    | 预热让一次性初始化完成；首次请求是新进程就绪后的第一条任务。                                   | 预热次数和排除规则固定，不能选择性排掉慢样本。                    |
| 模型加载 / 服务就绪 / 健康探针     | 分别是装入模型、服务可接受工作、检测状态的小请求。                                             | 健康探针通过后还要确认模型能完成最小请求。                        |
| JIT / 即时编译                     | Just-In-Time，在运行时生成或优化执行代码。                                                     | 可能提高首请求耗时，需要与稳定阶段分开。                          |
| 异步执行 / 设备同步                | 异步调用可在设备任务未完成时返回；同步等待其真正完成。                                         | 不同步可能只量到提交时间；同步本身也会改变性能。                  |
| 排队时间 / 在途请求 / 积压         | 排队是等待执行；在途是已发但未终结；积压是待处理工作累积。                                     | 在途数不等于 GPU 实际同时执行数。                                   |
| 并发 / 批处理                      | 并发是同时未完成的请求；批处理将多个输入合并计算。                                             | 客户端并发数、引擎批大小与活动请求数不是同一个参数。              |
| 到达率 / 请求率                    | 单位时间进入系统的请求数。                                                                     | 与同时存在多少请求的并发数区分。                                  |
| 负载发生器 / 开放负载 / 封闭负载   | 发生器发送请求；开放负载按计划到达；封闭负载等待完成后补充请求。                               | 封闭负载随系统变慢而减小发送率，不能冒充固定开放流量。            |
| 计划发送 / 实际发送 / 发送滞后     | 预定发请求时刻、真正发出时刻及差值。                                                           | 滞后可能来自客户端瓶颈，不能全归给被测服务。                      |
| 吞吐 / 完成请求率                  | 单位时间完成的请求或产出的 token 数量。                                                          | 分子和时间窗口要匹配；是否只计成功以及失败量需同时说明。          |
| SLO / goodput                      | SLO 是 Service Level Objective，预定服务要求；goodput 是单位时间满足已声明要求的有效请求数。      | 是否包含质量门槛需明示；不是总吞吐的同义词。                      |
| 饱和 / 可持续容量                  | 饱和是继续加负载不能相应增加有效产出；可持续容量还需满足质量、延迟及无持续积压等条件。         | 短时峰值不等于长期能承担的到达率。                                |
| 稳态窗口 / 排空                    | 稳态窗口是预热后按规则选定的计量时段；排空是停止新请求后等待在途请求终结。                     | 不遗漏尾部慢请求；窗口定义见执行说明 P9。                          |
| 加速比 / 扩展效率                  | 延迟加速比可用基线耗时/新耗时，吞吐加速比可用新吞吐/基线吞吐；同构扩展效率再除以设备数量倍数。 | 先声明目标；没有可运行基线时不计算虚构倍数。                      |
| 阻塞 / 通信开销                    | 阻塞是一个工作导致另一个等待；通信开销是设备间传输及其等待成本。                           | 单看利用率低不足以判断通信瓶颈。                                  |
| RTF / 实时因子                     | Real-Time Factor，离线媒体处理耗时除以媒体时长。                                               | 按真实时间喂流会包含等待输入，不能直接用该墙钟比值代表处理速度。  |

## 5. 能力与评分

| 术语及别名                          | 含义                                                                                        | 本项目使用边界                                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 真值 / 标准答案 / 金标准            | 用来判定输出的参考答案或人工核验标签。                                                      | 自动生成但未经核验的答案不自动是真值；人工金标准也可能需裁决。                                                                                                      |
| 自动评分 / 评分器 / 验证器 / oracle | 评分器给出成绩；验证器检查规则；oracle 是能提供预期结果的参考实现或答案机制。                | 都要用正确、错误及边界样本自检。                                                                                                                                    |
| 准确率 / 正确率 / 通过率            | 判正确或通过的数量占预定义分母的比例。                                                      | 约束级、字段级、整题级、任务级不可混称；失败分母需保留。                                                                                                            |
| 运行完成率 / 质量成功率             | 前者统计正常完成，后者统计验收通过。                                                        | 正常返回但答错只增加前者，不增加后者。                                                                                                                              |
| EM / 精确匹配                       | Exact Match，按规定规范化后与参考完全一致。                                                 | 规范化可能改分数，需固定大小写、空白及等价表达处理。                                                                                                                |
| precision / 精确率                  | 被判为某类或某行为的样本中，真正属于它的比例。                                              | 不等于总体准确率；例如调用决策的精确率。                                                                                                                            |
| recall / 召回率                     | 应识别出的目标中，实际识别出的比例。                                                        | 摘要必要事实召回、工具调用召回的分母各不相同。                                                                                                                      |
| F1 / token F1 / macro-F1            | F1 是精确率与召回率的调和平均；token F1 按规定 token 重合计算；macro-F1 先对每类算 F1 再等权平均。 | 词/字符分词规则及零分母处理要固定；评测分词不必等于模型 tokenizer。                                                                                                  |
| Spearman 相关 / Kendall 相关          | 两种衡量排序一致性的秩相关指标。                                                            | 并列值处理和所用变体需明确，二者数值不直接互换。                                                                                                                    |
| 成对准确率 / 偏好比例               | 前者判断两者正确次序的比例；后者是评审更喜欢某答案的比例。                                  | 偏好不代表事实正确；平局单列或按明确规则分摊。                                                                                                                      |
| 混淆矩阵                            | 按真实类别与预测类别交叉统计的表。                                                          | 可识别某些工具/类别被系统性混淆，而非只看总分。                                                                                                                     |
| 约束遵循 / 要求保持 / 澄清          | 分别是满足指令条件、多轮持续执行有效要求、在信息不足时询问必要条件。                        | 已撤销要求不应继续保持；问题越多不代表澄清越好。                                                                                                                    |
| 弃答 / 拒答 / 误拒 / 误弃答         | 弃答因不知道或信息不足；拒答是拒绝执行；误拒是拒绝合理请求；误弃答是本可回答却弃答。        | 与必要澄清、技术失败分开。                                                                                                                                          |
| 回答覆盖率 / 覆盖率-准确率          | 愿意给出答案的题占比；展示不同弃答/置信门槛下覆盖与正确性的变化。                           | 与题库能力覆盖率是不同概念。                                                                                                                                        |
| 忠实度 / 完整性 / 无依据事实        | 忠实度关注不歪曲来源；完整性关注必要信息保留；无依据事实缺少指定材料支持。                  | 无材料依据不自动等于现实世界事实错误。                                                                                                                              |
| 矛盾率 / 事实支持率                 | 输出事实与参考冲突/被材料支持的比例。                                                       | 要明确按事实点还是按回答计数，保留无法核实项。                                                                                                                      |
| n-gram / 重复检测 / 冗余            | n-gram 是连续 n 个指定单位；重复检测统计重复片段；冗余是无必要的信息重复。                     | 合法列表、代码和术语重复不能一律当故障。                                                                                                                            |
| chrF                                | 基于字符 n-gram 精确率与召回率的翻译文本相似指标。                                            | 辅助比较参考译文相似度，不独立保证译义正确；版本/参数固定。见[原论文](https://aclanthology.org/W15-3049/)。                                                         |
| JSON / 结构化输出                   | JSON 是一种结构化数据表示；结构化输出是按机器可解析格式生成内容。                            | JSON 合法不等于字段符合 schema 或语义正确。                                                                                                                            |
| schema / Schema / JSON Schema       | schema 描述字段、类型及规则；JSON Schema 是验证 JSON 的规范体系。                               | 需固定方言/版本与验证器，不能假定每个引擎支持全部规则。                                                                                                             |
| 类型 / 枚举 / 必填 / 嵌套           | 分别限制值的种类、可选值、字段是否必须出现、结构内再含结构。                                | 检查额外字段及边界值，不能只检查键名。                                                                                                                              |
| default / 缺省值                    | 字段未指定时的默认语义或配置。                                                              | JSON Schema 的 default 本身不在验证时自动补值。见[官方说明](https://json-schema.org/understanding-json-schema/reference/annotations)。                                 |
| grammar / 强制格式约束              | 引擎限制可生成的序列，使其符合语法或结构。                                                  | 能保证的只是所实现约束；字段事实仍需检验。                                                                                                                          |
| 严格解析 / 输出修复 / 代码围栏      | 直接按格式解析、对输出加工使之可解析、Markdown 代码块边界。                                  | 若先去围栏或修复，应标为另一流程，不能冒充一次原生通过。                                                                                                          |
| 工具调用 / 函数 / 参数              | 模型请求系统执行某个外部操作，并给出其输入。                                                | 选择正确函数、参数正确、真正执行成功分别评测。                                                                                                                      |
| 模拟工具 / 状态机 / 依赖图          | 模拟可控外部操作；状态机描述状态及变化；依赖图描述动作先后要求。                            | 可等价或可并行的正确路径不强制唯一顺序。                                                                                                                            |
| 独立验收 / 状态断言 / 隐藏测试      | 在 Agent 之外核对成果；断言是可验证条件；隐藏测试不向被测系统暴露。                           | 自报完成不能代替验收，验收自身误判需抽查。                                                                                                                          |
| Agent / 智能体 / 执行框架           | 围绕目标持续调用模型、工具并管理状态的系统；框架负责循环与环境交互。                        | 成绩属于整套系统，不只属于模型。                                                                                                                                    |
| 人工介入 / 必要授权 / 救援干预      | 人参与流程；必要授权是预定正常权限步骤；救援干预是额外帮助才能继续。                        | 三者分开记录，正常审批不自动算失败。                                                                                                                                |
| 首次成功 / 修复重试 / 重复采样      | 一次尝试成功；沿用历史反馈修正；重置条件后独立重新生成。                                    | 重试预算及反馈规则固定，不把三种结果混在一个成功率里。                                                                                                              |
| pass@k / k 次至少一次成功            | 关心 k 个候选中是否至少有一个通过；标准估计须按基准定义。                                     | 常用每题无偏估计为 1−C(n−c,k)/C(n,k)，再对题目平均；n≥k、c 为 n 个独立同协议候选中的通过数。继承反馈的修复不适用。见[HumanEval 论文](https://arxiv.org/abs/2107.03374)。 |
| k 次全成功 / 稳定成功                | 同一任务预定的 k 次尝试全部通过。                                                             | 比“至少一次成功”更严格；公开 k 及完整次数，不能由 pass@k 推导。                                                                                                         |
| 无效操作 / 循环 / 预算耗尽          | 操作无助于目标、重复且无进展、达到允许的时间/token/步骤上限。                               | 合理重试不一定是循环，阈值需预先定义。                                                                                                                              |

## 6. 多模态

| 术语及别名                    | 含义                                                                                     | 本项目使用边界                                                 |
| ----------------------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 模态 / 多模态 / 跨模态        | 模态是文本、图像、音频等信息形式；多模态使用多种形式；跨模态关联其信息。                 | 各模态分项测，不能只凭一种模态题得出总能力。                   |
| VQA                           | Visual Question Answering，根据图片回答问题。                                            | 图像可用、文本线索泄露、答案规则分别核查。                     |
| OCR                           | Optical Character Recognition，识别图片中的文字。                                        | 原生视觉理解与外接 OCR 再交给 LLM 是不同系统。                     |
| ASR                           | Automatic Speech Recognition，将语音转为文字。                                           | 转录正确与理解内容正确分开评分。                               |
| CER / WER                     | Character/Word Error Rate，字符/词错误率，常按替换+删除+插入数除以参考字符/词数。        | 可能超过 100%；空参考及分词处理需定义，中文词级分词尤其要注明。 |
| 模态编码 / 媒体解码 / 预处理  | 将媒体变为模型可用表示、读取压缩媒体、缩放裁剪等准备步骤。                               | 不是同一阶段；无内部事件时不能虚构分阶段耗时。                 |
| 分辨率 / 裁剪 / 缩放 / 多图   | 图像尺寸、取局部、改变尺寸、一次输入多张图。                                             | 原文件分辨率不等于实际送入模型的分辨率。                       |
| 音频采样率 / 分段 / 抽帧率    | 音频每秒采样点、切分音频段、从视频每秒抽取的帧数。                                       | 与遥测采样率、模型 token 速率分开。                              |
| 时序理解 / 时间定位 / IoU     | 理解事件顺序、找事件时间区间；Intersection over Union 是预测与真值区间交集长度/并集长度。 | 事件匹配规则、时间单位、空区间处理先固定。                     |
| 流式媒体 / 最终确认 / 丢块率  | 按时间逐步输入/输出媒体；结果不再修订的确认点；未处理或丢失数据块占比。                  | 最终确认延迟须注明从哪段输入结束开始计时。                     |
| 级联 / 外部 OCR 或 ASR           | 先由一个系统处理，再把结果交给下一模型。                                                 | 所有辅助模型、资源和网络依赖计入整套方案。                     |
| 消融 / 移除模态对照           | 去掉某种输入或组件，观察质量变化以判断贡献。                                             | 改动可能改变问题可答性；只在定义清楚的对照里解释。             |
| 素材劣化 / 噪声 / 模糊 / 压缩 | 对媒体质量施加可控破坏或有损处理。                                                       | 若真值已不可辨识，需重标或单列，不能仍要求猜出答案。           |

## 7. 实验与统计

| 术语及别名                                | 含义                                                                                  | 本项目使用边界                                                                                                                                                                            |
| ----------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 预跑 / 冒烟测试                           | 小规模检查流程能否运行、仪器和评分器是否可用。                                        | 3 次启动、5 次性能、30 分钟稳定性是预跑示例，不是正式样本量或标准。                                                                                                                          |
| 预注册 / 冻结协议                         | 在正式看结果前固定题目、指标、样本量、阈值和停止/重跑规则。                           | 更改后应形成新版本，避免根据结果反向挑规则。                                                                                                                                              |
| 受控比较 / 单因素变化                     | 宜保持其他条件一致，只改变关注的因素。                                              | 无法控制的差异即混杂，需记录，不能强行归因。                                                                                                                                              |
| 最佳方案比较 / 调参预算                   | 允许各方案使用适合自身的配置，并限制和公开寻找配置的资源投入。                        | 与相同配置的受控比较分开排名。                                                                                                                                                            |
| 混杂 / 相关 / 因果归因                    | 混杂是多个因素一起变化；相关是共同变化；因果归因指认定某因素导致结果。                | 相关不自动证明因果，例如热与降频同时出现。                                                                                                                                                |
| 配对比较 / 成对样本                       | 对相同题目或匹配运行分别测两个方案，再比较差值。                                      | 应保留配对关系；不同题库总分不能直接当配对差。                                                                                                                                          |
| 样本 / 样本量 / 重复次数                  | 样本是观察单位；样本量是其数量；重复是同条件再运行。                                  | 同一道题 100 次不等于 100 个独立问题。                                                                                                                                                        |
| 独立性 / 相关样本 / 聚类                  | 独立意味着随机变化不互相依赖；相关样本共享因素；聚类把同题族或运行块视为一组。        | 重采样单位需符合这种依赖结构。                                                                                                                                                            |
| 题族 / 运行块                             | 共享模板、来源或语义的一组题；在相近环境连续完成的一组性能请求。                      | 用于识别重复和相关性，避免虚增证据量。                                                                                                                                                    |
| 题库覆盖 / 代表性 / 外推                  | 覆盖说明测了哪些类型；代表性是样本反映目标总体的程度；外推是扩展结论到未测对象。      | 有很多题也不保证代表全部真实工作。                                                                                                                                                        |
| 描述统计 / 估计对象                       | 描述统计汇总已有结果；估计对象是希望由数据推断的总体特征。                            | 固定完整题集成绩与对真实任务平均表现的推断不同。                                                                                                                                          |
| 均值 / 中位数 / 标准差                    | 算术平均、排序中间位置、围绕均值的离散程度。                                          | 均值容易受极端值影响；标准差不是置信区间。                                                                                                                                                |
| 分位数 / 分位数算法                       | 排序分布中的指定位置及其插值规则。                                                    | P99 在少量样本下很不稳定，要报告数量和算法。                                                                                                                                               |
| 置信区间 / 95%区间                        | 在所用抽样假设下，某种构造方法长期重复约 95%覆盖目标参数的区间。                       | 不是“95%的请求都落在此区间”，也不自动包含题库偏差。                                                                                                                                       |
| bootstrap / 自助重采样 / paired           | 从已有样本重复抽取并计算统计量，以估计波动。                                          | paired 是 SciPy 等接口的配对选项；配对时保持配对，聚类时重采整组；不能治愈不具代表性的题库。见[SciPy 接口](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)。 |
| 退化分布 / 二项样本区间                   | 样本全相同时朴素重采样可能无波动；独立成功/失败数据可考虑二项概率区间。               | 全成功不代表真实失败概率为 0，相关样本也不能直接套独立二项公式。                                                                                                                           |
| 实用等效 / 最小实际差异 / 容差            | 差异小到对使用无意义的预定范围；容差是允许偏离程度。                                  | 本项目需区间落入预定范围才支持相应等效结论；不显著不等于相同。                                                                                                                            |
| 误差 / 偏差 / 不确定性                    | 误差是测量或估计偏离目标；偏差是系统性偏离；不确定性描述结果的未知范围。              | 多测几次可缩小部分随机波动，却不自动消除题库或仪器偏差。                                                                                                                                  |
| 统计显著性                                | 在指定统计假设下，观察差异与仅随机波动解释的相容程度。                                | 显著不保证使用上有价值；不显著也不能证明等效，仍需效应大小与区间。                                                                                                                        |
| 多重比较 / 校正 / 探索性结果              | 同时检验很多差异会提高偶然发现概率；校正控制相应错误；探索性表示尚不足以作确定结论。  | 小分差榜单应处理多重比较或显式保留不确定性。                                                                                                                                              |
| 百分比 / 百分点 / 相对变化                | 百分比表达比例；百分点是比例的直接差；相对变化再除以原值。                            | 60%到 66%是增加 6 个百分点、相对增加 10%。                                                                                                                                                    |
| 截尾观测 / 超时                           | 超时只知道耗时超过限制，真实结束时间尚不可见，属于右截尾。                            | 不能删除后只发“变快”的延迟，也不能当恰好在超时时刻完成。                                                                                                                                  |
| 条件分布 / 分母 / 排除规则                | 条件分布只针对符合条件样本；分母定义比例覆盖谁；排除规则定义谁不计入。                | 完成请求的延迟需同时展示未完成及失败情况。                                                                                                                                                |
| 停止规则 / 重跑政策                       | 何时结束采样、哪些失败允许重做及如何保留记录。                                        | 不能看到有利成绩就停，也不能只保存重跑成功结果。                                                                                                                                          |
| 温度停止 / 温停 | 设备温度达到冻结阈值时按政策停止运行的安全机制，如 engine-fit 的默认 85°C。 | 停止保留原因、计数与阈值来源；显式覆盖应另存原因，不等于放宽阈值。 |
| ABBA / 随机运行顺序                       | ABBA 按方案 A、B、B、A 交错测试；随机顺序打乱先后。                                      | 用于减轻顺序/温度漂移，不能消除所有环境差异。                                                                                                                                             |
| 盲评 / 评分锚点 / 位置偏差                | 隐去模型身份评分；锚点是分档实例；位置偏差是偏好展示顺序本身。                        | 交换左右位置、允许平局并保存分歧。                                                                                                                                                        |
| 模型裁判 / 人工校准 / 分歧裁决            | 用另一个模型评分；与核验的人工样本对照；处理不同评审意见。                            | 固定裁判版本与提示；裁判耗时是测评开销，不是被测系统耗时。                                                                                                                                |
| 一致率 / Cohen kappa                      | 一致率统计评审同判比例；kappa 进一步校正按边际分布估计的偶然一致。                     | kappa 主要适合两位评审的分类数据；类别极不均衡时谨慎解读，一致不保证正确。                                                                                                             |
| 置信度 / 概率校准 / 可靠性分箱            | 模型对答案正确的自报概率；校准检查它是否匹配实际频率；分箱按概率范围汇总。            | 缺失或无效置信输出单列，不自动截断修正。                                                                                                                                                  |
| ECE                                       | Expected Calibration Error，常按各箱占比加权“平均置信度与正确率的绝对差”。            | 分箱方式影响数值，需固定箱边界并报告各箱样本量。                                                                                                                                      |
| Brier 分数                                 | 本表二元版本为平均（p−y）²，p 是答案正确概率，y 为 0/1 正确标签，越低越好。                 | 多分类版本另有定义；自报分数未必是真实概率。                                                                                                                                              |
| 公开题 / 保留题 / 调参集 / 验收集 / split | 公开题已公开；保留题限制访问；调参集用于选配置；验收集用于最终检查；split 是数据划分。 | 同源改写题跨集可能泄漏，须按题族分割。                                                                                                                                                    |
| 数据污染 / 去重 / 近似匹配                | 测试内容进入训练/调参；去重识别重复；近似匹配找改写等相似内容。                       | 查不到重合不代表无污染，未知训练数据需披露。                                                                                                                                              |
| 合成题 / 最小对 / 平行题                  | 人工或程序构造题；仅差一个关键条件的配对题；不同语言表达同一问题的题。                | 都需核验答案与难度，自动生成不自动保证等价。                                                                                                                                              |
| 语义等价 / 规范化 / 数值容差 / 符号等价   | 同义答案、格式统一、数值允许误差、数学表达式表达相同含义。                            | 评分时允许范围预先定义，避免过宽或过严。                                                                                                                                                  |

## 8. 可信性与本地性

| 术语及别名                   | 含义                                                                             | 本项目使用边界                                                          |
| ---------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 幻觉 / 虚构引用              | 输出错误或无依据的断言；编造不存在或不支持主张的来源。                           | 区分事实错误、材料不支持和当前无法核实。                                |
| 可核查断言 / 证据定位        | 可被来源验证的具体主张；指出支持它的材料位置。                                   | 链接存在不等于支持答案。                                                |
| 离线 / 完全本地处理链        | 离线是规定流程不依赖外部网络；本地处理链指其计算与数据处理均在声明本地范围内。 | 下载后能生成一次不等于所有功能离线。                                    |
| 云端回退 / 降级行为          | 本地不可用时调用远程服务；条件不足时减少功能或性能。                             | 需触发相应错误路径并检查，不能只测正常请求。                            |
| 外发 / 遥测外发              | 数据离开被测范围；软件向外上传运行信息。                                         | 与本地采集性能“遥测”同词不同边界，要写清方向。                          |
| DNS / IPv6                   | DNS 将域名解析成网络地址；IPv6 是互联网协议的一个版本。                            | 外网隔离不能只处理 IPv4；DNS 查询本身也可能外发。                         |
| 宿主 / 代理 / 网关 / 出口    | 宿主承载虚拟环境；代理或网关可代转请求；出口是离开边界的网络路径。               | 被测进程不直连外网，也可能通过本地转发联网。                            |
| 抓包 / 连接审计 / 加密流量   | 记录网络包、核查进程连接、受加密保护的内容。                                     | 目标和时序可见不代表内容可见，包大小不能证明发送了什么。                |
| 沙箱 / 隔离环境 / 权限网关   | 限制程序可访问的资源；网关在工具调用时执行权限检查。                             | 运行生成代码需限制资源/网络并隔离真实凭据，容器不是所有平台的唯一方案。 |
| 合成标记 / 信息泄漏 / 跨会话 | 用虚构唯一内容探测数据是否越过用户或会话边界。                                   | 不使用真实秘密；零命中只表示此次未发现。                                |
| 越权尝试 / 越权成功          | 请求超出授权边界的操作；这种操作实际执行成功。                                   | 受网关拦截的尝试不能算实际越权成功，正常任务也要做对照。                |
| 提示词注入 / 工具返回干扰    | 外部文档或工具数据夹带指令，试图改变原任务或规则。                               | 用攻击/正常配对样本，报告攻击成功率与原任务质量。                       |
| 故障注入 / 正常探针 / 恢复   | 主动制造已知错误；持续发送正常请求观察影响；恢复正常服务。                       | 只在可恢复隔离环境执行，并记录触发位置。                                |
| 凭据 / 脱敏 / 受控存储       | 密钥等授权资料；隐藏敏感字段；限制访问的证据存储。                               | 保存完整证据与对外公开全文是不同操作。                                  |

## 9. 能耗与成本

| 术语及别名                         | 含义                                                                               | 本项目使用边界                                                |
| ---------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 功率 / 功耗 / 能耗                 | 功率是耗能速率；本表“功耗”指功率；能耗是累计消耗的能量。                           | W 与 J/Wh 不能混用，降低功率也未必降低每任务能耗。               |
| 整机插座功率 / GPU 部件功率         | 插座测供电端整机消耗；GPU 遥测覆盖指定部件。                                        | 两者范围重叠，不能相加；笔记本充电状态要控制。                |
| 总能耗 / 毛能耗 / 净能耗           | 总/毛能耗为完整窗口消耗；净能耗扣除同条件空闲基线估计。                            | 净值受基线误差影响，需与总值分开，不能静默替换。              |
| 功率积分 / 梯形积分                | 把每段功率乘持续时间累加；梯形法用相邻功率均值近似该段功率。                       | 采样缺段、时钟误差和短任务都会影响精度。                      |
| 校准 / 精度 / 分辨率 / 量程        | 仪器读数与参考对照、误差水平、可区分的最小变化、可测范围。                         | 高频采集不能补救低精度或传感器不刷新。                        |
| J/成功任务 / 批次分摊              | 同批全部尝试能耗除以成功任务数；无法逐请求归属时按声明规则分摊。                   | 失败和重试保留，成功数为 0 则不可计算；分摊不是逐请求直接实测。 |
| A 计权 / 等效声级 / 背景声          | 按人耳频率敏感度修正的声学计量；等效声级表示一段时间的等效声能；背景声是其他声音。 | 需固定距离和窗口；风扇转速不能代替噪声测量。                  |
| SOC / 电池健康 / 续航              | State of Charge，当前电量占比；健康描述电池可用能力；续航为可运行时长。            | 同样掉 10%电量不一定消耗相同 Wh；短窗口外推仅是估算。           |
| BOM                                | Bill of Materials，整机及配套部件清单。                                            | 不能只算 GPU 而遗漏电源、内存和散热等必需件。                   |
| TCO / 总拥有成本 / 全生命周期成本  | Total Cost of Ownership，在声明周期内归属方案的硬件、能源、维护等成本。            | 本项目用折旧分摊口径并另列现金支出，边界与周期须公开。        |
| 现金支出 / 折旧 / 残值 / 寿命      | 实际付出的钱、购置成本随使用分摊、周期末剩余价值、采用的可用年限。                 | 同周期不能重复计入购置全价和同一资产折旧。                    |
| 新增成本 / 机会成本 / 分配比例     | 本次额外支出、占用资源而放弃其他用途的代价、共享设备归属本方案的份额。             | 已有设备不是必然零成本；机会成本常是估计，需标来源。          |
| 利用率 / 忙闲比例 / 使用量         | 成本模型中设备被使用的比例、忙与闲时间分配、实际工作总量。                         | 与 GPU 传感器利用率区分，同名词不能直接代入公式。               |
| 每成功任务成本                     | 同周期或批次全部归属成本除以对应成功任务数。                                       | 成本边界、重试和失败应匹配分母。                            |
| 边际收益 / 增量产出                | 追加投入后增加的合格吞吐或成功任务等产出。                                         | 增量不为正不能推导正收益或回本。                              |
| 回本 / 盈亏平衡 / 敏感性分析       | 相对替代方案累计节省覆盖投入；两方案成本相等的点；改变假设看结论是否变化。         | 应明确替代方案和成本假设，不由“更快”直接推出。              |
| 人工活跃时间 / 等待时间 / 时薪假设 | 操作者真正工作时间、过程自动等待时间、将人工折算成本的单价。                       | 整个安装墙钟时间不能全计为人工。                              |

## 10. 工程、身份与证据

| 术语及别名                                                | 含义                                                                                | 本项目使用边界                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| API / 端点 / 接口合同                                     | API 是程序接口；端点是其具体访问地址/方法；合同定义输入、输出及行为规则。            | “兼容”宣称需逐功能验证，流式、取消和工具调用可能只实现部分。         |
| CLI / 原生桌面应用                                        | CLI 是命令行接口；原生桌面应用通过操作系统界面运行。                                 | 不假定桌面应用存在可用 API，人工测量要标精度。                        |
| 接口适配器 / 输出协议适配                                 | 把统一测试请求映射到某引擎接口，并解释返回格式的组件。                              | 不得通过适配悄悄改变任务或补全答案。                                 |
| 执行器 / 编排 / 运行方案管理器                            | 安排任务、控制预算并记录结果的程序；外部编排也可能管理服务生命周期。                | inferyard 的模型服务由操作者外部启动，CLI 不隐式管理服务。           |
| 版本 / revision / commit / main                           | revision 是所指版本；commit 是版本记录标识；main 通常是可移动分支名。                  | 不能只保存 main，需锁定不可变版本或内容哈希。                         |
| 哈希 / 校验值 / SHA-256 / digest                          | 从内容计算的摘要；SHA-256 是一种摘要算法；digest 常表示产物内容身份。                 | 可核对文件相同，不证明发布者可信或内容安全。                         |
| 权重分片 / 文件清单                                       | 一个模型可能分布在多个文件中；清单列出实际使用文件。                                | 每个权重、tokenizer 及配置都需校验，不能只哈希下载目录名。            |
| manifest / 元数据 / 环境快照                              | manifest 为机器可读清单；元数据描述对象；快照记录某次运行的环境。                    | 保存实际值、来源和未知项，使推荐绑定准确配置。                       |
| run / attempt / request；run_id / attempt_id / request_id | run 为一轮实验运行；attempt 为一次尝试；request 为单个模型请求；后缀\_id 表示各自标识。 | 一个 Agent 尝试可含很多请求，一题也可有多次尝试，避免混用分母。        |
| ID / 题目 ID / 孤立 ID                                      | ID 是标识；题目 ID 标识样本；孤立 ID 是找不到对应父记录的引用。                          | 标识唯一且关联可校验，不包含敏感身份信息。                           |
| URL / URI                                                 | URL 是网络资源地址；URI 是更一般的资源标识。                                          | 提交链接需解析到实际仓库和产物，镜像不自动等同原始内容。             |
| 输入输出日志 / 标准错误 / 退出码                          | 请求与结果记录；程序错误输出通道；程序终止状态码。                                  | 记录首个真实错误，退出码 0 不一定代表答案通过验收。                    |
| trace / timing / 阶段事件                                 | trace 为关联执行轨迹；timing 为计时数据；阶段事件记录进入/离开步骤。                  | 客户端不可见的阶段不能仅靠总时间拆出来。                             |
| usage / 端点计数                                          | 接口报告的 token 等使用量。                                                           | 需核实包含思考、模板、缓存的方式；不是无条件的实际生成 ID 数。         |
| 请求值 / 生效配置 / 默认值                                | 客户端传入值、服务端真正采用的值、未显式设置时采用的值。                            | 不支持的参数可能被忽略，无法核对时公开未知。                         |
| 容器 / 镜像 / 虚拟机 / 原生环境                           | 隔离/封装运行环境、可部署模板、虚拟化系统、直接运行在宿主上的环境。                 | 跨平台硬件访问不同，容器不能代替所有原生测试。                       |
| 编译 / 构建 / 转换 / 补丁                                 | 将源代码形成程序、组装可运行产物、改变模型分发格式、修改原有程序。                  | 记录输入输出版本、时间及改动，补丁需可获得。                         |
| 回滚 / 模型切换 / 停机时间                                | 恢复旧版本、更换服务模型、无法提供预期服务的时长。                                  | 切换后要检查残留状态与功能回归。                                     |
| 冒烟 / 回归测试                                           | 冒烟验证最小流程；回归测试检查变更是否破坏原本表现。                                | 代表集发现异常可扩展重测，不能用小集冒称全覆盖。                     |
| 复现配方 / 重放 / 复现包                                  | 足以重建配置的说明、按记录重新执行、配套文件与证据集合。                            | 性能允许事前容差，生成文本未必逐字相同。                             |
| 自测 / 另一操作者复跑 / 独立复现                          | 原团队测试、其他人重做、具有声明独立性的主体复现。                                  | 人员、设备、组织和利益关系分别披露；独立复现可选，不是当前验收门槛。 |
| 产物 / 证据包 / 账本                                      | 输出文件等成果、支撑结论的资料集合、逐次记录清单。                                  | 原始数据、汇总结果和报告应可关联。                                 |
| 不可覆盖记录 / 修订版本 / 过期标记                        | 保留旧内容的新写入方式、纠正后的版本、提示旧结论适用范围已改变。                    | 过期不表示历史数据自动为假，不静默删除或重写。                       |
| 计数守恒 / 覆盖校验 / 重算                                | 计划与执行等数量能对上；确认应有记录齐全；从原始证据重新计算。                      | 发现缺失要披露，不能事后伪造采样数据。                               |
| diff / 配置差异                                           | 两个版本或配置之间的改动清单。                                                      | 用于解释混杂、升级及回归，不能只比较名称。                           |
| null / 缺失值                                             | 表示没有可用数值，而非数值为 0。                                                     | 应附未测、不可测等原因；不同缺失原因不可吞并。                     |
| 许可 / 许可证 / 再分发 / 来源快照                         | 使用条件、向他人提供副本、保存检查时的来源版本。                                    | 许可核验不是自动法律结论；保存原题不代表可公开原题。                 |
| 实测 / 估算 / 外部引用                                    | 亲自按协议测得、根据公式和假设计算、引用他人结果。                                  | 三种证据明确标记，不能无标识混排。                                   |

## 12. 单位、时间与公式符号

| 术语及别名                   | 含义                                                                    | 使用规则                                                        |
| ---------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------- |
| byte / 字节；GB / GiB        | 字节是存储单位；GB=10⁹字节；GiB=2³⁰字节。                               | 内存表默认 GiB，不能把 GB 数值直接改标签。                         |
| bit / 位；B 参数量            | bit 是二进制位；模型参数量中的 B 常表示十亿。                              | 如“7B 参数”不是 7GB 文件；记录参数整数或明确估计。                 |
| s / ms                       | 秒、毫秒；1s=1000ms。                                                   | 延迟与时间戳精度同时注明。                                      |
| K / 1K / 4K / 8K             | 本方案长度扫描中的 K 约定为 1024 个 token。                                  | 正式记录用 1024/4096/8192 等整数，不假定所有外部工具同义。        |
| 请求/s / token/s / GiB/token | 每秒请求数、每秒 token 数、每 token 对应的内存增长量。                      | 只在声明边界和可观察数据下计算；KV 非线性时用曲线。              |
| W / J / Wh / kWh             | 瓦为功率；焦耳、瓦时、千瓦时为能量；1W=1J/s，1Wh=3600J，1kWh=1000Wh。   | 电费通常用 kWh，不能把 W 直接乘电价。                              |
| W/J                          | 表格中“W/J”表示功率和能量两类字段的并列简写。                           | 不是将瓦除以焦耳的计算指标。                                    |
| dB(A) / LAeq                 | A 计权分贝标记、指定时间窗口的 A 计权等效声级。                            | 声级按对数计量，不能简单算术相减背景分贝。                      |
| UTC / 时间日期               | Coordinated Universal Time，协调世界时。                                | 证据时间用 UTC 并保留当地显示时区，时长用单调时钟。               |
| t0 / t_content（tc）/ t_answer（ta）    | 请求开始发送、首个非空生成内容到达、首个可辨识答案到达的时刻。          | 同一客户端时钟，非内容元数据不触发后两者。                      |
| t_last（tl）/ t_end（te）               | 最后生成内容到达、完整响应正常结束的时刻。                              | 失败/超时保存终结事件，但不能假定存在正常 t_end。                |
| N_out                        | 指定覆盖范围的输出 token 数量。                                           | 记录实际生成、端点报告或重分词估计，按来源分组。                |
| t_end−t0 / t_answer−t0       | 完整请求耗时、首答案延迟。                                              | 两个事件应来自可对齐的同一计时口径。                          |
| (N_out−1)/(t_last−t_content) | 在真实逐 token 事件且 N_out>1 时的平均输出间隔速率。                        | 块接口不适用；用于公式的计数与时间事件应覆盖同一序列。        |
| E_joule / P_i / t_i / i / Σ  | 总能量（J）、第 i 次功率（W）、第 i 个时间点（s）、采样索引、求和。         | 梯形积分把相邻功率均值乘时间差累加；公式里的 i+1 为下一个采样点。 |
| p / y / n / c / k / C(a,b)   | Brier 中的概率与 0/1 标签；pass@k 中的总候选数、通过数、抽取数；C 是组合数。 | 含义随公式明确，a<b 时组合数按 0 处理；不是设备数。                |
| A / B；P0–P9；S1–S5          | A/B 是比较方案标签；P0–P9 为执行说明章节；S1–S5 为其中来源链接代号。       | 都是文档记号；P95 中的 P 是百分位，不是执行说明编号。              |

## 维护规则

新增分析指标、缩写或工具时，同步添加中文解释、适用条件和分母/单位。更换工具版本或改变定义时记录变化，不悄悄沿用旧指标名。此表的解释帮助阅读；实施仍以原始基准协议和本项目冻结的实验配置为准。
