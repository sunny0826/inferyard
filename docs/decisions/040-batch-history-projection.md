# ADR 040：批次历史投影与离线全量核验分离

状态：Accepted

## 背景

`run --plan` / `resume` 每次进入批次都会读取全部历史 run。原实现重复调用
`read_trial`，重建历史回答、资源、环境及全部指标。跨 workload 多次调用会重复执行
这些与后续发送决策无关的工作。原始批次 writer 不写 `summary.json`，不能以读取该文件
替代重建；它即使存在也只是可损坏、可重建的派生物。

## 决策

仅运行/续跑的历史读取使用命令内投影。冻结输入、身份、请求生命周期、评分、持续窗口
与服务排空按现有规则还原，批次身份、父子链、预算、服务切换和停止条件保持不变。
摘要的消费字段从事件重算，不信任派生摘要，也不填近似值。

这是明确的读取校验边界变更：投影不验证所有原始文件的字节哈希，不重放未消费事件，
不逐条校验采样、环境和调度。manifest 结构、文件存在性/大小及安全路径仍检查。
事件日志同次流式严格 JSON 解析并计算真实摘要，用于父子链绑定。内存日志只读取
末尾至多一字节，以保留截断对完整性的影响。

lab 排空仍检查观测身份、请求快照绑定、生命周期及释放状态；native 不能获得引擎排空
证明。此处的封存标记只表示存在合法 manifest，不能被用作全量核验成功的结论。

`verify`（包括批次）、`report`、`repeat-summary` 和 `repeat-check` 显式保留全量
`read_trial`，按原规则校验哈希、响应协议、采样和观测。此决策补充
[ADR 034](034-command-local-reuse.md) 在批次运行中的用途边界；
不改变其余命令内复用约束，也不改变 ADR 038 的格式支持集。

## 后果

证据格式和 writer 不变，无持久缓存；有效证据的全部历史消费字段保持等价。
省去反复的全量重建，但每次命令仍流式扫描各历史事件日志，不声称总体扫描复杂度
变为线性，也不据此声明实测提速。源码身份改变后的测量资格遵循
[血缘规则](../data-contract.md#证据血缘与比较结论)。

软件验收以多 run / resume / duration / capacity / lab / native 的字段等价和拒绝路径
回归证明；不代表真实模型运行或其他平台的原生验收。具体读取范围见
[数据契约](../data-contract.md#批次历史投影)。

单故障场景下投影与全量读取的错误码一致；同一 run 同时存在多类损坏时，两种读取
报告的优先错误可能不同（全量核验先做 manifest 哈希，投影先做绑定校验），两种路径
都会拒绝该 run。投影路径不保留两条仅影响证据语义、不影响发送决策的拒绝：
native 模式 `engine_internal_drain` 非空、非 lab 引擎出现 `lab_wire`/`lab_usage`
事件；`verify` / `report` 仍按原规则拒绝。
