# ADR 049：模型获取预算与失败诊断

状态：Accepted。日期：2026-10-11。基线：`597367d`。
实施与平台验证状态见 [backlog](../backlog.md#模型获取诊断与超时)。

## 问题与决定

`model acquire` 原先把 1800/180/60 秒同时作为默认值和不可增加的上限。
多 GB 文件在慢链路上可能无法在总期限内完成，失败却只返回一个通用原因。
依据 [issue #23 的操作者决定](https://github.com/sunny0826/inferyard/issues/23#issuecomment-6104737474)，
三个值改为默认值，允许操作者显式配置正有限秒数。20 GiB 文件上限保持不变。
这项决定只影响显式模型获取，不改变正式测评的停止条件、来源核验或服务生命周期。

父进程保管总期限、取消和回收，并根据子进程报告的实际网络进展执行读取期限。
仅依赖 HTTP 库的 socket 超时无法覆盖整个子进程停滞；只观察 `.part` 文件大小也不能
区分读取聚合、写入缓冲与无网络进展。进展必须来自实际读取，空闲心跳不能续期。
写盘、哈希和发布受总期限约束，不把它们的等待误报为网络读取超时。

诊断通过固定字段和允许值传递，公开失败阶段、异常分类和传输进度。
不转发子进程原始 stderr、异常文本、URL、请求头或响应正文。
现有 `limitations` 与退出码不扩张，操作者可以区分超时、连接失败和已有部分数据的失败。

## 来源记录与兼容

新增必需预算字段意味着新生产记录使用 `remote_model_source.v2`。
读取端保留原 `remote_model_source.v1` 的严格只读支持，不给旧记录补默认预算，
也不改写原件。远程元数据解析规则不变，parser 仍为 `remote-model-source-parser.v1`。
核心 `schema_version=3` 不变。字段及拒绝路径见[模型获取契约](../contracts/model-acquisition.md)。

## 取舍

- 仅补带宽说明不能满足操作者配置预算的要求；无限等待则失去有界回收，均不采用。
- 直接转发 stderr 能暴露更多上下文，但可能泄漏凭据或签名 URL，采用固定诊断字段。
- 本轮不增加 `--proxy-origin`。代理需要独立约定 CONNECT、代理鉴权、TLS 信任及
  仓库 Authorization 的处理；仅验证代理 origin 不能证明这些边界成立。
  当前保留直接连接，明确记录环境代理与系统代理不生效。

## 验证边界

软件验证覆盖非法预算、默认预算、显式扩展、预算记录、旧格式读取、脱敏、
持续小块数据、无数据读取、总期限、取消和强制回收。
Windows 使用本地合成流和自有子进程核验原生行为，不下载真实模型。
这些结果不证明原 sing-box TUN/Fake-IP 故障已经复现，也不授予真实 CDN 性能资格。
