# ADR 037：原始证据读取与封存呈现分离

状态：Accepted

## 决策

通用 `verify` 直接核验原始 run/batch/冻结计划与 engine-fit；未封存证据读完整前缀并返回 partial/3。
已存在但损坏的 seal 仍为证据错误，不能降格。封存核验成功与原执行是否完成分开表达。
engine-fit 在请求前保存身份检查点，不自动续跑或补造资源。

新 report v7、comparison v4、engine-fit manifest v2 封存保存的 HTML 与数据摘要，
默认核验字节和来源语义；当前渲染检查为显式选项。旧格式继续原重算规则。
普通来源采用相对路径及显式源根映射；携带包仍限制包内来源，不全盘搜索或默认复制大日志。

能力判定只对有来源绑定的数据计算一次；engine-fit 去掉无关 basename 限制，
保留内容、加载、模型路径、受控 MLX 脚本摘要与未知启动参数拒绝。

## 理由与代价

为了核验原件而生成中间报告增加步骤；要求当前渲染字节永远相同会混淆保存完整性与展示实现。
只删除 HTML 检查、把坏 seal 当中断或忽略 argv 都会降低来源保证，因此不采用。
代价是新旧格式与定位/语义两层核验。旧格式非空来源映射显式失败，不能静默忽略。

字段和退出码见[离线读取契约](../contracts/offline-reading-contract.md)。
