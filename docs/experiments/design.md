# 实验设计与验收约束

本文件规定冻结实验、重复、比较、采集与受限交付的规则。单次和实验使用[同一数据契约](../data-contract.md)；平台能力以 [README](../../README.md) 为准，统一格式不扩大实时执行范围。

## 冻结实验

每次正式实验冻结模型、引擎、题包、模板、参数、任务协议、顺序/种子、重复轮次、采样规则、停止阈值和预算。预览展示组合清单、生成请求数、最坏时间预算、磁盘与资源要求，不发送模型请求。预跑另存，不能看到正式成绩后再改样本量或挑选最好结果。

身份分别由 `experiment_id`、`trial_id`、`run_id`、`request_id`、`case_id` 表示实验、预定轮次、实际执行、请求和题目。每个变体保留题族、输入哈希、实际模板 token 数、长度档与位置。方法和指标定义版本独立于数据格式修订，既有 ID 不因重排重新编号。

| 协议             | 冻结内容                                          | 完整性与限制                                                                                         |
| ---------------- | ------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 固定题序         | 明确题目列表、顺序、重复次数和截止时间            | 五终态与计划守恒；取消、工具错误、未执行和无法评分单列                                               |
| 长度/输出扫描    | 输入档、输出预算、每格重复数、容量停止规则        | 记录实际输入和输出；接受长度不等于该长度质量合格，预算不等于实际输出量                               |
| 材料位置/多证据  | 文本、长度、位置、题族及确定真值                  | 长度与位置变体不是新增独立知识题；跨模型质量轨用相同文本                                             |
| 固定时窗持续负载 | 探针循环、发送时长、请求安全上限与排空截止        | `planned = null`；按实际发送记账。正常到时且排空闭合可完整结束；提前触发上限或安全停止不冒充完整时长 |
| 封闭并发         | 1/2/4 等预先选定档位、槽归属、发送/结束窗口和排空 | 独立在途账本；保留失败、取消与窗口末尾请求；吞吐和 goodput 可离线复算                                |

实验预算同时展示上限和预跑估计，不称为确定完成时间。长输入不能用短题中位数估算全部耗时；正式模型测量期间避免同机主动构建与测试。

## 题包与评分

基础包 40 题包含指令遵循和平面字段提取，组合包 120 题扩展给定材料问答、数学逻辑、文本分类与嵌套结构化输出。两个题包用于工具与分项能力验证，不代表全面模型基准。

题目、答案、规则及组合关系以内容哈希绑定人工审核。新增内容或受影响规则须重新审核；旧审核只有在原记录、原批准与内容等价可核验时才能继承。自动参考答案检查不能替代人工审核，`--diagnostic` 不满足正式验收。

自然生成和引擎强制 JSON/Schema 是不同协议，不混算。执行状态、质量、指标可测性和能力适用性分开；纯性能负载允许质量不适用。评分器异常保留请求执行状态与分母，不能用后来成功替换原失败。

## 重复、续测与比较

核心串行协议保持并发 1，每题没有隐式重试；计划重复与修复重试分开。续测只选择明确未执行项并创建新 run，中断请求保留 invalid，failed 不自动重发。跨会话续测只形成计划进度或子集观察，不能拼成连续完整性能试验。

| 比较模式        | 允许变化                             | 结论范围                                                               |
| --------------- | ------------------------------------ | ---------------------------------------------------------------------- |
| model           | 模型产物与对应模板                   | 固定设备、引擎和任务协议，比较模型方案，不将差异归因于参数量等单一因素 |
| config          | 冻结的一个因素，如线程数、量化或缓存 | 同一基座与任务；量化需可核验的同源 revision，多因素变化改为方案并列    |
| side-by-side    | 任意已保存方案                       | 展示结果和不可比原因，不生成因果差值、赢家或加速结论                   |
| device / engine | 指定设备或引擎作为被测因素           | 属于条件扩展，各自通过适配和计量验收，不能继承未实测成绩               |

比较核验测量/评分定义、源码哈希和采集来源。只有经过审核且可核验的兼容映射才可说明某次变化仅影响展示，不能添加通用强制可比开关。时间、PID、端口等定位差异不是实验因素；未知条件不当作相同。

重复统计先展示每轮值、有效样本和范围。区间分析明确估计对象及题目/轮次的配对或聚类关系，不能把 3 轮 × 40 题当作 120 道独立题。固定小题包不发布泛化能力置信承诺。质量、完成率、延迟、资源的资格分别判定。

## 采集与停止

[指标定义](metrics.md)保留单位、层次、窗口、来源、版本、分子/分母及缺测规则。34 组核心与 9 组条件指标描述实现要求，不保证每台机器都有全部传感器。真实读数缺失为 `null` 并说明原因；成功路径与缺测路径都须有软件验证。

总观察开销须覆盖采集、验证、队列、写盘、flush/fsync、封存等完整日志路径。使用冻结的配对负载与容差评估；不能用局部轮询成本或模拟通过代替实际性能比较资格。更改测量源码后重新验证，不自动继承旧成绩。

冻结停止条件至少覆盖可用内存、磁盘、可得温度阈值、外部负载/电源变化、取消和槽未知。不要主动制造主机 OOM；故障和越界路径使用隔离或模拟环境验证。

达到温度条件可形成有效热限制观测：保留来源、读数、阈值、停止原因、已完成/取消/未执行数量及覆盖限制。不要求强行跑满，不把 execution completeness 改为 complete，不把未执行题计为答错；也不能直接归因为模型独有发热、硬件故障或降频。已确认硬件或温度限制后不反复重试。

## 条件扩展的验收

| 扩展         | 独立证据要求                                                                            |
| ------------ | --------------------------------------------------------------------------------------- |
| 第二引擎     | 固定版本、模型哈希、模板计数、有效参数、空闲/取消及对应采集来源；仅 HTTP 兼容不足以通过 |
| GPU / 能耗   | 硬件、驱动/仪器、校准、时钟与窗口绑定；识别回绕和缺段；部件能量不当作整机能耗           |
| 封闭并发     | 多槽状态归属、在途与排空账本、统一窗口和可复算吞吐；负载端不能成为未披露瓶颈            |
| 原生工具调用 | 确定性模拟函数，工具选择、参数、执行与最终答案分别核验；不等于真实世界 Agent 任务       |
| 量化比较     | 同源认证、冻结单因素、双方可运行性和逐项比较资格；无高精度或其他基线时不估造收益        |

## 验收与受限交付

正式能力需要契约与故障测试、离线重算、对应设备真机证据，以及一致的报告/导出。损坏证据、缺少评分、模型失败和平台未支持分别报告。旧原件与封存哈希不变；历史迁移生成的新上下文和缺项可查，不冒充新的测量。

独立操作者复现及签收要求已取消；人工题包审核、原始证据核验和软件验收保留。不能以硬件限制掩盖尚未实现的软件。受限实测记录原因、接手步骤、验收条件和未完成计数，迁移到合适机器继续。

可选扩展与受限平台工作统一见[backlog](../backlog.md)，实际平台覆盖见[平台状态](../platforms.md)。
