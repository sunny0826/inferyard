# 指标定义与验收

本文件定义 34 组核心与 9 组条件指标，是 catalogue 的生成源。指标定义版本 `phase2.v1` 与活动数据格式 `schema_version = 3` 分别管理；定义存在不表示每个平台均可采集或已实测。任务规则见[实验设计](design.md)，平台与证据见 [README](../../README.md)。

目标不是凑指标数量，而是每个启用指标都能回答一个问题、给出证据、重算并判断可比性。下表共 34 组核心指标、9 组条件指标；同一指标的 P50/P95 或分组曲线不重复计数。

## 1. 共同记录与计算规则

每个指标定义至少包含：`metric_id / definition_version / unit / layer / source / window / applicability / required_capabilities / aggregation / comparison_policy`。观测/汇总附 `value / status / missing_reason / sample_count / numerator / denominator / excluded / evidence_refs`；不适用的字段可省略，禁止使用含义不明的 0 或空字符串。

层次区分请求、进程、设备、引擎与整机；缺测原因至少覆盖未支持、权限不足、传感器缺失、窗口无样本、边界不可识别、原证据缺失、计数来源改变和样本不足。支持状态、模型能力和本次是否纳入分别记录。

以下基础集合按冻结计划中的一个题型/实验单元计算：

- `P`：计划请求数；`C`：协议完整完成；`F`：有效执行但超时/断流/服务错误；`D=C+F`。
- `P=C+F+cancelled+invalid+not_executed`，五终态互斥。准备/探测/预热不进入正式分母。
- `Q`：完成且通过评分的请求。失败 F 按质量未通过处理，部分正确答案不抵扣失败；评分器错误是 unscorable，不改变执行状态。
- 完整质量轮次要求全部应测项有效执行且可判质量。取消、无效、未执行或无法评分时仅展示子集与计数，正式整包成绩为 null；纯性能包质量为不适用，不因此不完整。
- 零分母为 null。预算耗尽但协议完整属于 C，`budget_exhausted=true`，按实际答案评分；预算耗尽不是自动失败。结束事件缺失/断流属于 F。
- 资源缺测不改变执行与质量；环境变化按指标影响范围降低性能可比性。输出/字段不能为了提高分数被自动修复或补全。

固定时窗持续负载单独定义完整性：事前冻结循环探针、时长、请求安全上限、停止与排空政策，每个请求先持久化身份再发送。P 为本次已登记请求数，仍按五终态守恒；未使用的上限槽位不计 not_executed。到时按协议停止发送并完成排空、所有已登记请求归入 C/F 且必需证据齐全才是完整持续实验；提前安全停止/触发请求上限/工具中断为未达时长。分窗质量只描述已执行探针，不冒充完整 120 题成绩。

百分比同时给分子/分母；差值以百分点或原单位表达。所有正式指标均保留原始值，不只存格式化百分比。

## 2. 执行与质量：12组

各项按定义、来源和冻结窗口计算；实现状态由安装包 catalogue 记录，真实采集资格绑定本次设备与证据。

| ID  | 指标             | 定义与分母                                         | 必要证据与比较限制                                                                                          |
| --- | ---------------- | -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| R01 | 完成率           | C/D；并列五终态、P和实际执行数                     | 终态事件；不完整仅作已执行部分观察，不算整包差值                                                            |
| R02 | 超时率           | timeout/D                                          | 错误原因与冻结deadline；用户取消不混入超时；工具自动deadline必须算超时                                      |
| R03 | 失败类型率       | 每个互斥主错误类型数/D；未知单列                   | 保留原error；按首个有证据的原因分类，不把连锁取消算多次故障                                                 |
| R04 | 输出预算耗尽率   | D中budget_exhausted为真的请求数/D；另列C中的耗尽数 | 原finish reason、输出预算；cancelled/invalid中的耗尽另列诊断不入分子；耗尽不决定答案是否正确                |
| Q01 | 分类别整题通过率 | 各类Q/D；不将六类合成一个总分                      | 评分器、题包、答案处理版本；失败纳入分母；另给每轮值                                                        |
| Q02 | 约束通过率       | 通过的预注册约束数/所有有效尝试应检约束数          | 单独标识计分约束，内部解析/非空检查不重复算内容约束；失败的约束计不通过                                     |
| Q03 | 严格JSON解析率   | 通过严格JSON解析的请求数/结构化任务D               | NaN/Infinity、重复key、围栏、解释文字按冻结规则；不先修复再解析                                             |
| Q04 | Schema合法率     | 满足指定Schema的请求数/结构化任务D                 | 冻结Schema版本及实现；解析失败计不合法；Schema合法不等于语义正确                                            |
| Q05 | 字段准确率       | 正确字段路径数/所有有效尝试应输出字段路径数        | 固定必需字段和数组匹配策略；解析失败/执行失败全部字段计错；缺字段不删分母，额外字段另影响Schema/整题        |
| Q06 | 材料问答EM       | 规范化后精确命中允许答案数/问答任务D               | 固定Unicode、空白、标点等规范化，不运行后扩充同义答案；开放式语义评分不混入                                 |
| Q07 | 数学逻辑正确率   | 正确答案数/数学逻辑任务D                           | 明确绝对/相对误差、单位、答案提取规则；NaN与无穷非法；不执行模型代码                                        |
| Q08 | 分类macro-F1     | 固定K类各F1平均；F1=2TP/(2TP+FP+FN)                | 非法标签/执行失败进入预定无效预测列，真类计FN；K类固定，不删除无人预测类别；零分母类按冻结约定并显示support |

Q03/Q04/Q05 同时展示：JSON 可解析、Schema 合法、字段正确和整题通过；不能用其中之一代表其他三个。所有 Q 指标的成功贡献须来自 C，F 即使部分输出可解析且内容正确也不计通过，仅保留诊断信息。强制格式与自然输出是不同协议。

## 3. 延迟与速度：7组

客户端使用同一单调时钟：`t0` 发送，`tc` 首非空生成内容，`ta` 首可识别答案，`tl` 末内容块，`te` 协议完整结束。reasoning 可影响 tc，不一定影响 ta；界面渲染时间不在当前客户端计时边界内。

| ID  | 指标            | 计算与单位                           | 适用性与验收重点                                                                                                 |
| --- | --------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| L01 | 首内容延迟      | (tc−t0)，ms                          | 排除元数据、心跳、空内容；块接口称首内容，不声称逐token TTFT                                                     |
| L02 | 首答案延迟      | (ta−t0)，ms                          | 能可靠区分答案/reasoning；完整空答案为null/no_answer_event；同时保留质量失败                                     |
| L03 | E2E分布         | (te−t0)，ms；min/P50/P95/max、样本数 | 仅C且计时有效；并列超时率/预算与排除量；超时不得以deadline补入完成分布                                           |
| L04 | 端点输出吞吐    | 端点输出token数/E2E秒，token/s       | 使用同次请求usage，记录范围；非decode速度，不做跨tokenizer排名；缺计数为null                                     |
| L05 | 内容块间隔      | 相邻非空生成块到达时间差，ms         | 接收端在脱敏缓冲前记录到达时间/通道/序号等纯元数据，不保存敏感原文；同请求至少2块；不是ITL，分块策略不同不可比较 |
| L06 | 引擎prefill速度 | 实际未缓存处理输入token数/prefill秒  | 需要同请求阶段计时与缓存定义；TTFT不能代替；完整缓存命中且处理量0时不产生速度                                    |
| L07 | 引擎decode速度  | 引擎定义的生成token数/decode秒       | 冻结首token、思考/特殊token范围与计时定义；不能用E2E减首内容反推引擎时长                                         |

L06/L07 为核心数据契约和适配器扩展点；实际 Prism 构建是否可读须实测确认，无接口则 null。上游 llama-server 文档描述了 `timings` 及缓存/输入/生成计数；这是适配依据，不是 Prism 分支已通过的证据。[llama-server 官方说明](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

统计默认按**题型/负载档/轮次**分组，不把长短任务混成一个性能结论。L01/L02 的主分布也仅取 C；失败中已观测首事件可作为独立诊断分布。L05 先给逐请求统计，禁止把长答案产生的更多块当作更多独立请求。

v1 测评落盘的 content/reasoning 文本可能经脱敏缓冲延后、拆分或合并，不能据此还原接收块间隔；v1 缺少原块元数据时 L05=null/evidence_missing。L01/L02 可使用已有的脱敏前首事件时间戳，不依赖落盘文本块边界。

分位数算法冻结，宜使用 nearest-rank：排序后第 `ceil(p*n)` 个。P50 在偶数样本时与 v1 测评的两中位均值可能不同，应注明定义版本。原 v1 测评 median 继续按原定义显示，不静默改名覆盖。

本项目的呈现规则：n < 20 不显示 P95，返回 insufficient_samples；20 ≤ n < 100 可展示 P95，但标探索性；n ≥ 100 仍应给样本构成/相关性限制，不自动意味着可靠尾延迟。此为呈现规则，不是统计充分性的行业阈值；核心不承诺 P99。每格 5 次扫描只展示全部点、中位数和范围。

## 4. 资源与环境：8组

系统/服务/引擎/设备层指标分列，不相加为所谓总内存。指标归属正式 C+F 请求窗口；基线、预热、取消、无效及残留活动另列。采样观测峰值不等于真实瞬时峰值。

| ID  | 指标             | 计算与单位                                            | 适用性与验收重点                                                                                                |
| --- | ---------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| C01 | 最低系统可用内存 | 正式窗口MemAvailable最小值，bytes                     | `/proc/meminfo`；缺段给覆盖与限制；不能称模型独占内存                                                           |
| C02 | 服务RSS峰值      | 绑定PID/starttime正式窗口RSS最大值，bytes             | 不采客户端RSS；子进程范围显式；PID变化停止该来源                                                                |
| C03 | 服务RSS增量      | 正式RSS峰值−预热后空闲基线中位数，bytes               | 明确基线窗口；可为负不截为0；不是模型权重大小或泄漏量                                                           |
| C04 | 服务CPU时间      | 同PID/starttime两累计样本间用户态＋内核态CPU秒差      | 保存实际sampled_start/end与覆盖比例；部分窗口只称观测区间CPU时间；完整请求值须边界证据齐全；计数回退/重启为缺测 |
| C05 | 服务CPU利用率    | ΔCPU秒/同一对累计样本的Δ墙钟秒×100%，100%为一个逻辑核 | 不能用部分样本CPU差除整个请求E2E；整机归一化率另名并记录可用CPU数/cpuset                                        |
| C06 | 换页活动         | pswpin/pswpout累计差，pages与按实测页大小换算bytes    | 系统层；zram/swap环境注明；不归因到单模型；计数回退不可算负交换量                                               |
| C07 | 温度             | 对已知sensor/domain报告时间线与观测最高°C             | 只读能力探测；权限/来源不明为null；不能凭升温断言热降频                                                         |
| C08 | 频率             | 按来源报告per-core/policy频率时间线，Hz               | 声明requested/reported/effective；来源语义不同不可混排；不把请求频率当实际执行频率                              |

每个 collector 记录读取起止、配置/实际间隔、丢样、开销与 phase。C04/C05 需在可归属边界采样；窗口内不足两个可核验累计值则 null，不用运行前后无关样本填补短请求。覆盖不足按指标降级，不删除慢请求。

## 5. 长度与重复稳定性：7组

| ID  | 指标                        | 计算与证据                                                                        | 不能推出的结论                                                                 |
| --- | --------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| X01 | 输入长度—接受/完成/质量曲线 | 每个实际输入档列P、拒绝数、C/D、Q/D、延迟与资源；固定模板计数与输出预算           | 服务接受长输入不等于理解有效；最末通过档不等于理论极限                         |
| X02 | 材料位置/多证据正确率       | 每个长度×位置×题族的正确数/有效执行数；文本hash与真实token数                      | 单针命中不代表长文理解；变体不作独立题数量                                     |
| X03 | 输出预算达成与结束分布      | 实际输出量、预定目标、finish reason、预算耗尽；严格定长轨另列达到目标数/D         | 自然回答提前EOS不是执行失败；未生成到上限不等于不支持输出长度                  |
| S01 | 分窗延迟漂移                | 冻结早/晚窗口或逐窗口L03，报告中位差/比值及样本/失败率                            | 样本组成必须相同或按case配对；漂移不等于热降频                                 |
| S02 | 空闲点RSS漂移               | 相同探针周期结束并确认idle后RSS差/时间序列；重启对照独立                          | 缓存与保留池未排除时不能宣称泄漏                                               |
| S03 | 重复任务通过一致性          | 每case各轮pass/fail；全k轮通过题数/预定做满k轮的去重case数；未完整k轮则整包值null | 例如30题全3轮通过为30/40，不含只跑一轮的新80题；不称修复重试成功率或标准pass@k |
| S04 | 运行间性能波动              | 相同case/负载各完整trial中位数、范围、IQR与配对差                                 | 三轮只描述已观测变化；不能凭少量相关数据作泛化显著性结论                       |

S03 例子中的“新 80 题”指组合包在基础包 40 题之外扩展的四类 80 题，题包组成见[实验设计](design.md)。

持续负载用固定发送窗口，结束后排空至冻结 deadline；窗口末仍在途的请求保留到最终终态。按发送时点归属请求队列、按完整请求报告延迟，资源时间线另保留排空段，不能截掉窗口末慢请求。比较早晚时固定相同探针组成，并冻结 `min_completed_per_case_per_window`；不足则 S01 差值/比值为 null，不能借用 P95 的 20 样本呈现规则。

本地容量预检未发送与资源安全停止后的未发送项记录 not_executed 及原因。服务拒绝已发出的合法请求（例如 400/413/503 容量或能力错误）、OOM 或超时，均按冻结协议记 F 及具体原因，不能因 HTTP 未接受就删除分母；工具发出违反冻结协议的请求时记 invalid，并保留归因证据。所有未测档可见，不把未测写成“不支持”。

## 6. 有条件扩展：9组

以下条件指标按[扩展验收要求](design.md#条件扩展的验收)分别验证来源、接口与实际设备；条件不满足时保留原因，不用估算值填充。

| ID  | 指标              | 计算边界与证据                                                                                 |
| --- | ----------------- | ---------------------------------------------------------------------------------------------- |
| E01 | GPU内存观测峰值   | 按设备/进程/引擎层分别采样bytes；统一内存不能与RSS相加；关联具体设备和进程证据                 |
| E02 | GPU利用率         | 按厂商指标定义/刷新周期记录%；不是算力效率或模型GPU驻留证明                                    |
| E03 | 功率              | 明确CPU package、GPU board或整机插座，W；硬件计数差推导的是窗口平均，不冒充瞬时读数            |
| E04 | 能量              | 同域能量计数差处理回绕，或同范围功率时间积分，J；覆盖缺段不静默插值为完整测量                  |
| E05 | 每成功任务能量    | 冻结批次所有执行尝试能量/质量成功任务数，J/成功任务；零成功为null；预热/加载是否计入须单独命名 |
| N01 | 请求吞吐          | 固定批次C/(最后终态−首次正式发送)秒；失败/排空留在分母时间；开放/封闭协议分开                  |
| N02 | 达标吞吐goodput   | 同时满足预注册质量和时延要求的请求数/同一批次秒数；阈值运行前冻结                              |
| N03 | 真实ITL与服务排队 | 两个子项分别存：同token序列的逐token事件间隔；同服务端时钟执行开始−入队；缺真实事件则各自null  |
| U01 | 启动到可用时间    | 托管或外部可核验的启动事件→就绪→首个有效答案分别记录；热启动/新进程/OS缓存状态分开             |

N03 为一组条件观测目录，ITL 和排队不是同一数值、不能合成。U01 在服务生命周期边界扩展前仅允许有完整外部时间证据的导入，不能用服务探测耗时冒充启动时间。

Linux powercap 的 RAPL 暴露能量计数及计数范围；package 和子域可能包含关系，不能相加重复计量，也不能声称为整机插座功耗。[Linux powercap 官方文档](https://docs.kernel.org/power/powercap/powercap.html)

## 7. 关键手算与故障验收

这些是指标 fixture，不是正式模型成绩；优先测计量风险，不用重复实现细节的低价值测试堆数量。

| 用例                                                                        | 精确预期                                                                                                   |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 4个有效请求，3完成1超时；2题通过；完成中1题length结束且正确                 | 完成率3/4，超时1/4，质量2/4，耗尽1/4；超时不进完成耗时分布，length不改执行完成                             |

## 8. 与方法目录的关系

方法目录的类别号与类内编号形成稳定 ID，保存原名和版本，不因重排重新编号。目录范围大于当前自动化能力；不能用“条目齐全”宣称全部方法已实现。

| 方法目录覆盖方向               | 对应指标                                |
| ------------------------------ | --------------------------------------- |
| 兼容性、基础能力、中文、结构化 | R01～04、Q01～08                        |
| 内存、性能、上下文             | C01～08、L01～07、X01～03               |
| 配置/量化、稳定性              | S01～04及受控配对                       |
| 设备、身份、统计、证据         | 所有指标的资格、来源和谱系              |
| 能耗、并发、启动维护           | E01～05、N01～03、U01；分别验收的条件项 |

通用计量背景见[方法执行说明 P2–P5/P9](../reference/methods-guide.md)，活动执行与质量语义以[数据契约](../data-contract.md)及本文件为准。模型答错与执行失败分开，不能为得到有利结果改变分母。
